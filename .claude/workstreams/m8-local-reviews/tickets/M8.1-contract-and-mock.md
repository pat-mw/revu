## Goal

This ticket **is** the specification for local-only reviews. It implements decision **D6** (`LOCAL_REVIEWS.md`
§3): the mock is the permanent oracle, its semantics *are* the contract, and revud conforms to it afterwards
— never the reverse. Concretely it lands three things: the reserved id bands of **D2** (§3.1) in
`packages/shared` with their disjointness argument encoded as tests; the smallest possible additive extension
to `RevuApi` + `ROUTES` (`listBranches`, `createLocalReview`, `listLocalReviews`, `deleteLocalReview`) using
only allowlisted `:param` names so no invariant test needs amending; and a working local-review implementation
in the mock adapter, reachable under `?mock=1` with no network. Because D2 keeps review identity a positive
integer, **every existing `RevuApi` signature, every existing route, both routers' integer gates, the `/pr/:n`
route family and every React Query key stay byte-identical** — this ticket adds, it never edits. It gates all
of M8.2–M8.7: the store tables, the git snapshot builder, the write sink, the daemon dispatch and the two app
tickets all conform to what lands here.

(different files, no shared symbol). **M8.1.3 depends on M8.1.1 and M8.1.2**; **M8.1.4 depends on M8.1.3**;

## Constraints that bind this ticket

- **The frozen contract is `client.ts` + `types.ts`** (hard-constraints; AGENTS.md "Ownership & verification"
  lists both as read-only inputs). This ticket is the sanctioned exception, and only for **additive** change:
  a new method, a new type, a new route entry. Any deletion or signature edit in those files is a defect.
- **The three transport semantics must survive on the local path** (`http.ts:226`): `submitReview` →
  `head_moved` is a 200-level **value**; `syncPull` may resolve with `partial` set (locally it will be `null`,
  but the key must be present); `getSnapshot` → `null`, never 404-as-error. M8.1.6 asserts each on a local id
  because M8.4/M8.5 conform to what the mock does, not to what the doc says.
- **D2's payoff is only real if the routes use allowlisted params.** `:n` only. Enforced twice, in
  `draft-isolation.test.ts:118` and `token-custody.test.ts:243`, and neither file may be edited.
- **The mock adapter is never deleted and `?mock=1` stays reachable in production builds** (hard-constraints).
  Local reviews must therefore work fully in the mock with no daemon and no git.
- **Migration doctrine applies to the mock store too.** `store.ts:176-179` states it: bump the version, add a
  defaulting step, never touch the corruption check. A v3 document with drafts must open, migrate, and keep
  every draft.
- **Identity: email is a key, never a body.** The synthesized `GhUser` carries the git-config *name*
  (§4.1); `Human.id` (the lowercase email) may be stored on a local comment record but never rendered into a
  comment body.
- **No stamping locally** (§6). `prefixBody` exists only because N humans share one GitHub bot; the mock's
  local submit must skip it, or M8.4 will faithfully reproduce the wrong spec.
- **Draft isolation is preserved verbatim.** The mock keys drafts `humanId → prNumber`
  (`store.ts:73`); a local id is just another `prNumber`, so isolation holds with no new mechanism. Do not
  introduce a parallel local-draft keyspace in the mock.
- **Code comments carry no tracking artifacts** (AGENTS.md). No `M8.1`, no ticket ids, no phase names in any
  source or docstring this ticket writes. M-ids belong in this file only.

**Three decisions are recorded here rather than left open**, because M8.1 merges first and downstream tickets
are already written against the answers. Reversing one is a contract change, not a preference; later tickets
cite them by letter.

- **D-a — the mock's `listPulls` includes local reviews.** M8.5.3 mandates the daemon-side merge, M8.6.2/M8.6.4
  render the inbox from `usePullList`, and `PrLayout` resolves a review only out of that list
  (`pr-layout.tsx:280-282`) — a local review absent from `listPulls` renders the "isn't in this installation"
  screen on every open. `listLocalReviews` still exists, for management surfaces (delete, M8.10) and for the
  local-only annotations under D-c. The cost is deliberate: `scenarios.test.ts:61`/`:64-67` and
  `scripts/smoke.ts:54-61` are updated in M8.1.5 and M8.11.2 rather than loosened.
- **D-b — a submitted local `ReviewSummary` never enters `snapshot.mutable.reviews`.** It is persisted as a
  local record (`local_reviews_submitted`, M8.2.5) and read by nothing on the render path, so §4.1's and §7's
  "issue comments and submitted reviews are always empty" stays true after the first submit. The alternative
  (append on submit) would silently falsify M8.7.4's threads-only Conversation tab. M8.4.3's snapshot write and
  M8.7.4's premise both cite this.
- **D-c — the two local-only annotations (`dirty`, `archivedPr`) ride `LocalReviewSummary`, not
  `BrokerPullMeta`.** `BrokerPullMeta` (`types.ts:278-301`) is frozen and its §4.1 field table has no room for
  either; `LocalReviewSummary` is new here and already mirrors the `local_reviews` columns, both of which are
  columns. So: **`listPulls` stays the row source** (D-a) and `listLocalReviews` supplies only the local-only
  annotations, queried under its own key. Nothing renders a row from both sources, which is the "two truths"
  hazard M8.6's open question 1 named. Consumers: M8.5.2 (the route must return both fields), M8.6.4 (the
  dirty badge), M8.7.8 (the dirty banner), M8.9.5 (the superseded state — its open question 3 resolves here
  unless its owner escalates).

## Landmines

- **Widening `RevuApi` breaks four files at once.** `packages/app/src/api/mock/adapter.ts:212`,
  `packages/app/src/api/http/adapter.ts:163` (the only two implementations), and — via `ROUTES` — the
  exhaustiveness guard at `packages/revud/src/api-router.ts:375`. Splitting these across commits leaves the
  tree red; that is why M8.1.4 is deliberately atomic. *Missed:* the branch cannot pass `bun run check` at any
  intermediate commit and bisect becomes useless.
- **`fillPath` throws on an unknown param.** `token-custody.test.ts:244` sweeps every route through
  `fillPath(route.path, { n, sha, threadId, id })`. A route with `:branch` or `:ref` throws inside a test that
  never mentions local reviews, producing a confusing failure far from the change. *Missed:* a red gate whose
  cause is three packages away.
- **The two id bands are not mutually disjoint.** `LOCAL_ENTITY_ID_BASE` (9e12) is above
  `LOCAL_REVIEW_ID_BASE` (1e9), so `isLocalReviewId(someLocalCommentId)` returns **true**. The predicate is
  namespace-scoped: apply it to review ids only. *Missed:* a comment id routed as a review id in M8.5's
  dispatch — a bug that will look like data corruption.
- **The fixture local review in `listPulls` breaks `scenarios.test.ts` — and D-a guarantees it will.** `:61`
  asserts exactly 10 items and `:64-67` asserts the exact pull-number array; `scripts/smoke.ts:54-61` asserts
  the same two things and is in **no gate**. *Missed:* a failing test that reads like a flake and gets "fixed"
  by loosening an assertion that was pinning real behaviour — or, for smoke.ts, a silent breakage nobody sees
  until someone runs it by hand.
- **The shared mock store leaks across `bun test` files.** One process-wide `localStorage` shim, debounced
  ~1s persistence; any suite driving `createMockApi`/`mockDev` must `mockDev.reset()` in `beforeAll`.
  *Missed:* green locally, red on the slower CI runner, order-dependent.
- **Bumping `STORE_VERSION` without a migration step, or adding the new field to the corruption check**
  (`store.ts:189-202`), reseeds the document. *Missed:* every existing draft is destroyed on upgrade — a
  direct violation of "drafts survive everything".
- **Stamping on the local path.** Because of D6 the mock defines the spec; a `prefixBody` call left in the
  local submit becomes the contract M8.4 conforms to, and the two latent optimistic-path bugs named in §6
  (unconditional stamping in the synthetic reply, empty-`brokerLogin` attribution on resolve) get inherited
  rather than avoided. *Missed:* `**Name** (role)` rendered as literal body text on a local review.
- **Negative or zero ids anywhere on the local path.** `direct-router.ts:150` rejects them, and negatives are
  reserved for optimistic synthetics (`threads.ts:121`). *Missed:* a locally minted comment id that orphans the
  optimistic entry it was meant to replace (§8, edge 17).
- **The design doc's method/route arithmetic is wrong.** §2 says "21 `RevuApi` methods" and §3.1 says "all 21
  HTTP routes"; the code has **19** of each. Harmless here, but do not derive anything from the doc's counts —
  re-count from `client.ts:39-116` and `http.ts:40-70`.
- **Route shadowing in `api-router.ts:133`.** Matching is by segment count with `:param` matching anything, in
  insertion order. Any new route that shares its segment count and literal prefix with an earlier entry is
  silently swallowed by it. Verified safe for the four proposed paths; re-verify if the spellings change.

## Open questions

1. **Wire shapes for `BranchRef`, `CreateLocalReviewInput` and `LocalReviewSummary` are not specified.**
   §4.2 gives store columns and §7 gives picker requirements; no wire type exists. Proposal: mirror §4.2's
   columns in camelCase for `LocalReviewSummary`. Implementer decision, but it freezes on merge.
2. **Exact route spellings.** `/api/branches` + `/api/local-reviews` are a proposal, not a decision. Every
   later ticket and the fetch adapter hard-code them; pick once.
3. **What does `listBranches` return in the mock, and does `BranchRef` carry a default-branch marker?**
   There is no git repo behind the mock, so a small fixed fixture branch list is the obvious answer — but the
   *shape* is decided here for both transports, and two consumers depend on it: M8.6's picker needs local
   branches **and** remote-tracking refs (§8 edge 3), and M8.6's open question 7 asks what the base picker
   defaults to, which is answerable only if `BranchRef` carries a `default` marker. Answer the shape question
   once, here; M8.3's `listBranches` git read and M8.6's picker both conform to it.
4. **How does the mock mint local ids?** §3.1 specifies `MAX(id) + 1` from a SQL `UNIQUE(repo, base_ref,
   head_ref)`; the mock has no SQL. Either a second persisted counter alongside `store.ts:522` or an
   in-document max scan. Whichever is chosen must make duplicate creation return the **existing** review
   (§8 edge 6) so the mock and M8.2 agree.
5. **Scope boundary on `deleteLocalReview`.** M8.1 declares the method and route; M8.10 owns deleting rows,
   pinned refs and snapshots. Decide whether M8.1's mock implementation deletes the full local record (and
   M8.10 only adds ref/immutable pruning) or whether M8.1 stops at removing the review from the list. The
   daemon-side half of the same boundary is settled: M8.5.2 leaves `DELETE /api/local-reviews/:n` on the
   honest known-route 501 until M8.10 lands.
6. **`getRateLimit` on a local review.** §7 says suppress the rate chip on local reviews, but `getRateLimit`
   is a global read with no PR argument, so nothing in the contract changes. Confirm that the suppression is
   purely an M8.7 rendering concern and that no local-aware variant is needed here.
7. **Which `ApiErrorCode` do the creation errors map to?** `types.ts:538` offers only
   `network | rate_limited | not_found | forbidden | conflict | broker_unreachable | persist_failed` — there is
   no `invalid`/`bad_request`. `ref_not_found` → `not_found` is clear; `same_ref`, `unrelated_histories` and
   `shallow_clone` have no home. M8.3 raises this and correctly names it **this ticket's territory** — but
   M8.1 is the first ticket to merge, so by the time M8.3's implementer reaches the question the union is
   already frozen, which is why the decision moved here. Decide in M8.1.2: squeeze all three into
   `conflict`, or add exactly one
   code (and with it the `vApiErrorCode` entry and the `http.ts:165` status). M8.3.2 produces the typed builder
   errors and M8.5.2 maps them; both need this settled before they start.
8. **What shape is a thread id?** Nothing parses them (`direct-router.ts:440-456` passes `params.threadId`
   through opaquely, `fillPath` encodes it), so both a `PRRT_`-shaped id and a `local:<n>:<seq>` form are safe.
   M8.4's open question 2 framed this as an implementer call to be "mirrored back into the mock under M8.1" —
   but M8.1 gates M8.4 and will already have merged with the mock minting *something*, and D6 makes the mock
   the spec. So the choice is made **here**, in M8.1.3, and M8.4.2 conforms to it. The tradeoff: maximal
   client-indistinguishability (`PRRT_`-shaped) versus obvious locality (a `local:` prefix makes a mis-routed
   local id visible in a log).

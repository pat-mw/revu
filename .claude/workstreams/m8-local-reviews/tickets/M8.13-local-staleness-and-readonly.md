## Goal

The 2026-09-02 landing audit found the feature complete and the gate green on the chain tip, and it found a
short list of places where a **local review behaves differently from what the code around it promises**. This
ticket is exactly that list, filtered to one kind: runtime behaviour whose correct answer is already written
down somewhere — in a docstring, a guide sentence, a mock the daemon is supposed to conform to, or a message
that names a remedy — so no owner ruling stands between reading the gap and closing it.

Four of them are user-visible defects a reader can hit on an ordinary afternoon:

- **A local review never goes stale before a Re-sync** (`D8A-g1`). The daemon serves the list row's compare
  key and head SHA off the stored review row, stamped by the same sync that stored the snapshot — so the two
  sides `useStaleness` compares are the same value by construction, `stale` is structurally false, and the
  seal never turns gold on a branch that moved under the reader. The mock, which is the specification, already
  reads live ref tips and says so in its docstring; revud is the divergent transport, so conforming it needs
  no decision.
- **Read-only after a deleted or renamed branch is only half-enforced** (`M8.8-g2`). Submit and reply resolve
  the head first and refuse with a typed `not_found` naming the ref; resolve and react consult only the store
  and mutate stored threads on a branch that is gone. The project's own definition — "read-only means the
  stored content cannot change at all" — and the archive path, which refuses all four verbs, both say
  otherwise. Nothing on the screen says the branch is gone, either — and the mock cannot model a vanished ref
  at all today, so the refusal has no specification to conform to until M8.13.1 writes one.
- **The author-date under-report survives in two badges** (`EC2-g3`). The exact expression M8.8.3 removed from
  the reconciler is still in the files tab's per-thread badge and the author queue's counter. A rebase
  preserves author dates, so both report **0** on precisely the rewrite that moved the most work.
- **A failed pin is reported to nobody** (`D8A-g6` / `D5-g4`). The sync carries `pin: { ok: false }` and no
  route, log line or surface reads it, so a workspace whose `update-ref` fails loses its collection guarantee
  with no visible sign at all.

Around them sit four smaller behaviour fixes of the same shape: the inbox section that promises to drop to the
bottom once every local review is closed and instead sits at the top (`D7-g1` / `D9-g1`); the branch listing
that promises to re-read on every dialog open and re-reads only past a ten-second window (`M8.6-g2`); the
create dialog's title field, which **appends** what the human types to the pre-filled branch name (the audit
critic's find, already recorded as a board follow-up); and "Re-sync to rebuild", a remedy the re-sync itself
cannot perform for two corruption shapes (`D8A-g5`).

**What this ticket is not.** It carries no design decision, no contract-shape change to `RevuApi`, and no
owner question. The gaps that do need a ruling — OQ10's archived-review composer, ruling 4's unbounded live
pin set, delete-on-an-archived-review's unspecified semantics — are not here.

### M8.13.1 — Serve the local list row from live ref tips
**Do:** make the served row describe the branch pair **now**, which is what the mock's `listLocalPullRows`
docstring already specifies ("the compare key is read from the ref tips as they are NOW, not from the last
sync") and what revud does not do.

- Add a live-range read to `LocalReviewSurface`: given a review id, run `git rev-parse --verify` on the row's
  base and head refs, `git merge-base` on the two tips and `git rev-list --count <mergeBase>..<head>`, all
  through `runGit` — a git argv assembled without `--end-of-options` never spawns at all and the call silently
  no-ops, so nothing here builds an argv by hand. `resolveLocalRange` (`local-sync.ts:265`) already does the
  first three and is the thing to reuse or model on; note it answers `ok: false` for `same_ref`, which is a
  legal state for a list row and must not become a refusal here. The read **answers**, never throws: a list of
  many reviews must not fail because one branch was deleted. A head ref that no longer resolves comes back as
  an explicit unresolved value.
- `localPullListItem` (`direct-api.ts:502`) takes that live range and serves `broker.compareKey`,
  `pull.head.sha`, `pull.base.sha` and `broker.commitCount` from it rather than from the stored row.
  `localCompareKey(review)` (`:436`) stops being the row's compare key source; keep it only if something still
  needs the stored key by name.
- **When the head ref does not resolve**, serve `pull.head.sha` as the empty string — the same "not known"
  marker this function already uses for `repo.default_branch` — and keep the **stored** compare key, and serve
  `broker.commitCount` as the **stored snapshot's `commits.length`**. All three together are what keeps the
  screen honest: an unresolved head must leave `stale` false and `newCommits` **0**, so no Re-sync is offered.
  A vanished branch is not staleness the reader can act on: turning the seal gold and offering a Re-sync that
  can only fail would be a worse screen than the branch-gone banner M8.13.3 draws off exactly this signal.
  (A review with no stored snapshot has no commit list to fall back to; serve **0**, which is what the stored
  row answers today.)
- **An archived review reads no tips at all.** Its snapshot is frozen at the last sync
  (`local-surface.ts:947`) and its row must stand at the same instant, so `localPullListItem` uses the stored
  row whenever `archivedPr !== null` and runs no git for it.
- `localPullListItems` and `DirectApi.listPulls` become `async`; the router awaits it
  (`direct-router.ts:546`). The narrow `PullListSource.listPulls` (`direct-api.ts:417`) stays synchronous — it
  reads the poll cache and touches no git. The ETag still hashes the rows **as served**
  (`reviewListEtag`, `:455`), which now moves when a tip moves; that is the point, and it is what stops a
  client 304-ing forever over a branch that advanced.
- **The mock is the specification and already reads live tips, but its tips never move**: `liveRefSha`
  (`api/mock/local.ts:62`) is deterministic per `(repo, ref)`, so the spec's own rule is unobservable. Add one
  dev hook — a per-`(repo, ref)` tip override consulted by `liveRefSha`, with a string moving the tip and
  `null` removing the ref so `listLocalPullRows` serves an empty head SHA — on `mockDev`
  (`api/mock/devtools.ts:41`), beside `setLatency` and `setFailureMode`.
- **Then pin, in the mock, the three states this hook makes reachable**, because the mock is the specification
  and *"where the mock leaves a state undefined, pin it there first"* is one of this ticket's binding
  constraints. Turning the hook on without them would leave the spec and revud divergent in exactly the places
  this unit creates:
  - **An archived row reads no tips**, matching the daemon rule above: `listLocalPullRows`
    (`api/mock/local.ts:381-399`) serves the stored record's `baseSha`/`mergeBaseSha`/`headSha` and its compare
    key whenever `archivedPr !== null`, rather than the live tips it reads today for every row regardless.
  - **A removed head ref serves `head.sha = ''` and the STORED compare key**, and `commitCount` unchanged —
    not the `` `...` `` the empty tip would compose today, which would make `stale` true on the spec and turn
    the seal gold beside the branch-gone banner: the worse screen this unit exists to avoid.
  - **The write path refuses on a removed head.** `syncLocalReview` (`api/mock/local.ts:536-542`) would today
    stamp `''` as the record's `headSha` and mint a snapshot revud refuses with `ref_not_found`; it, and
    `submitReview`, `replyToThread`, `resolveThread` and `addReaction`, answer a typed `not_found` **naming the
    ref** in that state. This is the spec M8.13.3's daemon half then conforms revud to.
  Each of the three gets its own case in `api/mock/local.test.ts` with a positive control beside it — the same
  read, the same verbs, on a review whose head still resolves.
- Add **two** rules to the **shared** local suite so all three legs are held to them:
  1. **The row rule.** After a sync, moving the head tip with no sync in between must move the served row's
     compare key and head SHA away from the stored snapshot's.
  2. **The vanished-ref rule.** With the head ref removed through the same hook, all four write verbs refuse
     with a typed `not_found` naming the ref, and the stored threads and the saved draft come back
     byte-identical afterward.
  Reading a row inside the suite needs `'listPulls'` **added to the `LocalReviewApi` key union**
  (`conformance/local-suite.ts:76-89`), which is a key-pick over `RevuApi` that omits it today; nothing else
  about the config's shape changes. The hook is **declared**, not assumed — in the shape `compare` is declared
  (`conformance/local-suite.ts:116`, in `LocalReviewConformanceConfig` at `:99-123`), a runner supplies either
  a tip-movement function or the literal "unavailable" — because leg F drives a spawned daemon the test process
  cannot reach into, and a leg that silently skipped would read as green. Legs **E** and **G** declare the hook
  and run both rules; leg **F** declares it unavailable in words.

### M8.13.9 — Make a re-sync rebuild over an unreadable snapshot envelope or immutables row
**Do:** every snapshot read the local surface makes goes through `rebuildable`
(`local-surface.ts:659-682`), which turns the store's `StoreUnreadableError` into a typed `not_found` advising
"Re-sync it to rebuild from the repository". A message that names a remedy is a promise, and for two corruption
shapes the remedy cannot be performed, because the re-sync reads the corrupt row first:

- **The envelope.** `performSync` reads the authorship map through `store.getLocalCommentAuthors(localId)`
  (`local-surface.ts:760`), which parses the whole `local_snapshots` row (`store.ts:1957-1968`) and throws.
  Read it through the same catch-and-treat-as-absent shape already in this file (`storedIfReadable`,
  `:687-694`), answering the empty map. Losing an authorship map that a corrupt envelope was the only copy of
  is the honest cost, and it is smaller than a review nothing can ever open again — but it is a real cost, so
  the test records it rather than leaving it to be discovered.
- **The immutable row.** The snapshot write reads the existing immutable row for the same compare key to carry
  its `partial` forward (`ownImmutablePartial`, `store.ts:1404-1410`, called at `:1478`) and throws on an
  unparseable one. Treat an unreadable existing row as carrying no `partial`: the write that follows replaces
  that row **whole** with content addressed by the same compare key and freshly read from git, so nothing
  readable is being lost — the store's "a present row is real state and must not be silently overwritten" rule
  exists to protect a caller who would clobber state they cannot rebuild, and this caller is rebuilding exactly
  that row. **Change this one function only.** `parseRow` (`store.ts:957-962`) and every other read stay strict;
  a softening there would turn honest corruption into silent data loss on paths no sync can repair.

  one caller — `writeSnapshotRows` (`store.ts:1460-1493`) — which both `putSnapshot`

  The defence is the same one, unchanged by which transport filled the row: the read is immediately followed by
  a write that replaces the row whole, addressed by the same compare key and freshly fetched — from GitHub
  instead of from git — so the only thing an unparseable row could have contributed is a `partial` flag no
  reader can parse anyway. What is **not** softened is any path that reads without writing: a `getSnapshot`
  over the same corruption still throws `StoreUnreadableError`, on both transports.

## Constraints that bind this ticket

- **The mock is the specification and revud conforms to it.** M8.13.1 exists because the mock's row docstring
  and revud's row disagree; the mock's sentence wins. Where the mock leaves a state undefined, pin it there
  first — undefined behaviour in the mock is a future transport divergence.
- **The frozen contract stays frozen.** No method, route, field or error code is added to `RevuApi`,
  `LocalReviewSummary`, `PullListItem` or `BrokerPullMeta` by any unit here. Every fix is a change to what an
  existing field carries or to what an existing verb does.
- **Drafts survive everything**, and nothing here may make one unreachable. M8.13.3 refuses two more verbs and
  M8.13.9 rebuilds over corruption; both must leave the draft byte-identical, and both assert it.
- **All data goes through `api` from `@/api`** — never `@/fixtures`, never `@/api/mock`, outside the mock's own
  tests and the conformance runners.
- **The identity rule holds:** a local review is named by its `base ← head` pair, never by its number. The
  branch-gone banner names the ref, not the id.
- **`globals.css` is a read-only shared input** — compose existing tokens, no raw hex, no new class. Red means
  destructive; violet is reserved for draft/pending state; the branch-gone banner is neither.
- **Comments and docstrings are self-contained.** No unit's code may reference a ticket, a PR number, a phase,
  a session, an agent or an audit id. Those live in this file and in commit messages.
- **Every code change lands with its tests**, and shared conformance assertions live in
  `packages/shared/conformance` and run as matrix legs — never as a fourth copy inside a runner.

## Landmines

- **Ticket line pointers rot.** Every anchor in the table above was read on the `board/m8-closeout` tip. Read
  the seam before editing it; if the line moved, fix the anchor in the same edit rather than working around it.
- **A guard comparing two quantities that move together asserts nothing.** M8.13.1's whole subject is two
  values that are the same by construction today, so "served key ≠ stored key" is not enough on its own — pin
  the served key against a compare key computed by an independent `git` call. Same for M8.13.9: assert against
  the fixture's own `headSha`, never against a value re-read from the store being repaired.
- **A fix landing in the same edit as its test has no observed red.** Obtain one by control on every unit:
  restore the defect, watch the named test fail, revert, verify the revert byte-for-byte, and record both
  observations in the `## Log`.
- **A hardened git argv silently no-ops.** An argv without `--end-of-options` never spawns; M8.13.1's live probe
  routes every call through `runGit` and passes refs as `revs`, exactly as `resolveLocalHead` and
  `resolveLocalRange` do.
- **`listPulls` going async touches the router, not just the api.** `direct-router.ts:546` calls it
  synchronously; a missed `await` there serves a `Promise` as the body and the 304 branch reads `undefined`.
  The router's conditional-GET tests are the guard.
- **An archived review must read no tips.** Its snapshot is frozen and its row has to stand at the same
  instant; a live probe on an archived review would make the frozen snapshot and the live row disagree, and the
  freeze exists precisely so they cannot.
- **A never-synced local review has an empty head SHA too.** M8.13.3's predicate must gate on a stored snapshot
  as well, or every freshly created review renders as read-only with its branch gone.
- **An empty `pull.head.sha` reaches more than one surface.** Anything rendering `shortSha(pull.head.sha)` on a
  local row has to survive the empty string once M8.13.1 can serve it. Sweep the row and header renderers.
- **`mode-copy.ts` exports must be functions of `mode`, pinned on both readings** (`mode-copy.test.ts:1117`).
  The sweep is not a filter that drops what it cannot handle: it **refuses non-function exports**
  (`:1138-1150`) and **refuses any function that answers the same on both modes** (`:1152`). So M8.13.3's copy
  must be a function that really varies, and M8.13.2's mode-invariant sentence has no legal shape in this
  module at all — which is why it stays in `pr-layout.tsx`.
- **A Radix `DialogContent`/`TooltipContent` static-renders to the empty string.** Any new body asserted on
  real HTML must be its own portal-free component, or the test asserts on `''` and passes forever.
- **Softening one store read is one function, not a policy.** M8.13.9 changes `ownImmutablePartial` and the one
  authorship-map read; `parseRow` and every other read stay strict, or honest corruption becomes silent loss on
  paths no sync repairs.
- **The mock cannot express a base advance, and that is a fixture property, not a gap.** `listLocalPullRows`
  sets `mergeBaseSha = headSha` (`api/mock/local.ts:386`), so the compare key moves iff the head moves and
  `useStaleness`'s `baseMoved` is unreachable on every mock-backed leg. M8.8-g4's row shape — head SHA
  standing still, compare key moved — can therefore only be pinned on the direct leg, in
  `local-resync.test.ts`. Do not try to write it into the shared suite; it would be red on E and F for a reason
  that has nothing to do with the contract.
- **`@tanstack/query-core` is not a dependency of `packages/app`.** M8.13.7's `QueryObserver` comes from
  `@tanstack/react-query`, which re-exports it. Importing from `query-core` fails at module resolution — before
  any assertion runs — so the "today the counter reads 1" red is never observed and the recorded control is a
  fiction.
- **A source-scan block pins spelling, not behaviour.** `create-local-review.test.ts:252-286` reads the module
  as text. An assertion added there about what the request carries pins the shape of an expression and would
  stay green if the expression were correct and the call site wrong. Behaviour goes through
  `reduceCreateLocalReview` or the mutation harness.
- **`ownImmutablePartial` is on the pull-request path too.** Its one caller, `writeSnapshotRows`, is shared by
  `putSnapshot` and the local snapshot write, so M8.13.9's softening changes how a **PR** sync treats a corrupt
  `immutables` row as well. That is intended and defended in the unit; it is not a local-only change and must
  not be described as one.
- **Leg F cannot reach into its daemon.** It spawns revud as a separate process, so it declares the
  tip-movement hook unavailable in words. A leg that quietly skipped the new case would read as green and prove
  nothing.
- **`showsInInbox` deliberately keeps archived local rows.** M8.13.5 moves where the section sits; it must not
  change which rows the inbox lists, or an archived review's only copy of a human's work leaves the one screen
  that lists reviews.

## Open questions

None of the nine units waits on an owner ruling — that is the ticket's admission criterion, and any gap that
turned out to need one belongs on a different ticket rather than here. **One unit deliberately closes only
half of an existing question:** M8.13.6 takes M8.8 OQ3's ruling-free option (a daemon log line) and leaves the
two that need one (a row field, an inbox badge) with the owner. That is not a unit waiting on a ruling — the
line lands either way — but it does mean OQ3 is struck **with a qualification**, and the remainder is written
onto `BOARD.md` rather than disappearing with the strike. Two implementation choices are recorded because a
cold agent will meet them, and both are decided in this file rather than deferred:

1. **Where the corrupt-immutables repair lands (M8.13.9).** *(a)* In `store.ts`'s `ownImmutablePartial`, which
   is the read that throws; *(b)* in `local-surface.ts`, by having the sync clear a corrupt immutable row
   before writing. **(a) is chosen**: the write immediately following the read replaces that row whole with
   content addressed by the same compare key, so treating an unparseable row as carrying no `partial` loses
   nothing readable, whereas a delete-then-write from outside the store opens a window between the two
   statements that the store's single `BEGIN IMMEDIATE` transaction exists to close. Either satisfies the
   unit's Check; (b) needs an owner only if it grows into a general softening of `parseRow`, which this ticket
   forbids.
2. **How the app learns a branch is gone (M8.13.3).** *(a)* From the live row — `pull.head.sha === ''` on a
   review that has a snapshot; *(b)* from the sync's typed `not_found`, held in client state. **(a) is
   chosen**: it needs no contract field, it is continuously true rather than true only just after a manual
   sync, and it matches this feature's own rule that read-only is derived and never stored
   (`local-resync.test.ts:1-27`). (b) would put a persistent screen state behind a mutation result, which is
   the second source of truth the design has avoided everywhere else.

Two questions this ticket **answers on other tickets** when its units land, and which the executing agent
should strike there rather than leave open:

- **M8.8 Open question 3** ("where does a failed pin surface?") is answered by M8.13.6 **in part**: a daemon log
  line, warned once per sync that attempted a pin and failed. Strike it with that qualification — the log line
  is invisible to an app user, and whether a failed pin should ever reach a *screen* (the row field and the
  inbox badge OQ3's other two options name) is still the owner's call. M8.13.6 records that remainder on
  `BOARD.md`'s follow-up register rather than letting the strike swallow it.
- **M8.8 Open question 8** ("re-sync is unfollowable for two corruption shapes") is answered by M8.13.9: the
  sync treats an unreadable row as absent and rebuilds it.

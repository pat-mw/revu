## Goal

Make the PR chrome tell the truth on a local review. This ticket implements the frontend half of **D2**
(`LOCAL_REVIEWS.md` §3): because a local review keeps a positive-integer id, the entire `/pr/:n/*` route
family, every query key and both `matchPrNumber` regexes stay untouched — so the whole variance collapses to
a single `mode: 'github' | 'local'` derived from `isLocalReviewId` and threaded through the chrome (§7). It
lands three things. **Tabs:** Checks and Description are omitted and Conversation keeps only its threads
section, following the established "omit the group entirely rather than render it empty" precedent set by the
dev-controls capability probe — except that omitting a *tab* has no precedent today and is genuinely new.
**Identity:** `base ← head` and a `local` seal where a PR shows `#347`, no `#1000000001` anywhere (§3.1), no
author banner, and a 404 state that does not blame a GitHub App installation. **Copy:** an enumerated sweep
of every string that asserts a GitHub fact, ranked so that the actively harmful ones — those that instruct
the user to do something impossible, or claim a write that never happened — are fixed first and pinned by a
test. It also carries the two app-side pieces no other ticket owns: **D3's user-facing half** (the
uncommitted-changes banner — M8.3 detects it and M8.2 stores it, and nothing rendered it) and the **two latent
optimistic-path bugs** §6 says must not be inherited, both of which live in `state/threads.ts` and were handed
here by M8.4.7. The staleness and reconcile vocabulary is **correct as-is locally** (§7) and this ticket must
not touch it; that reuse is the strongest part of the feature and a well-meaning sweep is exactly what would
break it.

## Units

Default execution order below. **M8.7.1 gates every other unit** — it defines the derivation everything else
branches on. After it lands: **M8.7.2, M8.7.3 and M8.7.8 all edit `pr-layout.tsx` and must run in sequence**;
**M8.7.4, M8.7.5, M8.7.6 and M8.7.9 are mutually independent and independent of the `pr-layout.tsx` group**
(disjoint files), so all four can run in parallel with each other and with M8.7.2/M8.7.3/M8.7.8. **M8.7.7 is
the closing proof and runs last, after all eight others** — it is numbered before M8.7.8/M8.7.9 only because
it was written first; read the dependency, not the number.

The decomposition is chosen so that copy is *testable*: the repo has no DOM test runner (no RTL, no jsdom in
`packages/app` — see Landmines), so a mode-varying string is only checkable if it lives in a pure module a
`bun test` file can call. `components/review/error-copy.ts:1-12` already establishes exactly that pattern for
`HEAD_MOVED_TITLE` ("so the string has one source of truth the dialog renders and a test can pin"); this
ticket extends the pattern rather than inventing one.

### M8.7.1 — The mode derivation, defined once
**Do:** Add `packages/app/src/lib/review-mode.ts` exporting `type ReviewMode = 'github' | 'local'`,
`reviewMode(n: number): ReviewMode` — `isLocal(n) ? 'local' : 'github'`, where `isLocal` is **imported from
`lib/local-reviews.ts`** (M8.6.1), which holds the app's single call to `@revu/shared`'s `isLocalReviewId`.
Never a re-spelled `n >= 1_000_000_000`, and never a second direct call to the shared predicate: M8.6.1 claims
that call site and M8.7.4's grep enforces the claim, so a second one here would turn that check red the moment
both tickets are on `main`. Also export `useRouteReviewMode(): ReviewMode | null` which reads the
current path with the existing `/^\/pr\/(\d+)(?:\/|$)/` matcher and returns `null` when no review is open.
Move `matchPrNumber` into this module and re-point `app-shell.tsx:43-46` and `palette.tsx:49-52` at it — two
identical copies exist today and this ticket would otherwise add a third. **The regex is not to be changed**:
§3.1 explicitly depends on a synthetic positive integer matching `(\d+)`, and a "tidy-up" that admits
non-digits silently breaks `g f` / `g c` and the palette's "This PR" group. Inside the PR subtree the mode is
**threaded as a required prop** (PrLayout derives it once and passes it down); the two out-of-subtree
consumers (`app-shell.tsx`, `palette.tsx`) render *above* the router and can only route-derive, which is what
`useRouteReviewMode` is for.
**Files:** `packages/app/src/lib/review-mode.ts` (new), `packages/app/src/lib/review-mode.test.ts` (new),
`packages/app/src/components/app-shell.tsx`, `packages/app/src/components/palette.tsx`.
**Check:** `bun test packages/app/src/lib/review-mode.test.ts` passes with `reviewMode(347) === 'github'`,

### M8.7.9 — The two optimistic-path bugs, not inherited
**Do:** `§6` names two latent bugs in `packages/app/src/state/threads.ts` that "must not be inherited" by
local reviews. `MILESTONES.md`'s M8.4 seed assigned them to M8.4; M8.4's Surface is `revu:revud` and both
fixes are app-side, so M8.4.7 hands them here and owns only the response shape that makes convergence
possible. Fix both:
- **Unconditional stamping in the synthetic reply** (`threads.ts:161`): `syntheticReply` always calls
  `prefixBody(session.human, body)`, so the optimistic comment renders `**Name** (role)` as literal body text
  until the unstamped server comment swaps in. Stamp only when the session is a stamping session — the same
  condition the server uses, read off the session rather than off the review's mode, because today's
  unconditional stamp is wrong in **direct** mode too. This is a small, real behavior change for existing PR
  reviews in direct mode, not a local-only branch; that is deliberate and belongs in the commit message.
- **Empty-login attribution on resolve** (`threads.ts:292`): the optimistic flip sets
  `resolvedBy: { login: session.brokerLogin }`, which is `''` in direct mode and on every local review.
  Resolve to the acting identity instead, so the optimistic value and the value the server returns
  (`threads.ts:303-318` copies `resolvedBy` straight out of the response) agree rather than swapping visibly.

Keep the negative-id discipline (`threads.ts:120-124`) exactly as it is — it is what keeps optimistic ids
disjoint from the locally minted positive ones (`§8` edge case 17).
**Files:** `packages/app/src/state/threads.ts`, `packages/app/src/state/threads.test.ts` (or a new co-located
pure-module test if the stamping/attribution decisions are extracted, which is the preferred shape given
there is no DOM runner).
**Check:** `bun test` over the extracted derivations: a stamping session stamps and a non-stamping session
does not, asserted by round-tripping the produced body through `parsePrefixedBody` (`identity.ts`) and
expecting a parsed prefix in the first case and `null` in the second; and the optimistic `resolvedBy` is never
`{ login: '' }` for any session shape. Plus `bun test packages/app/src/components/review/failure-drills.test.ts`
green **unamended**.

## Constraints that bind this ticket

- **The frozen contract is a read-only input.** `packages/shared/src/api/client.ts` and `types.ts` are not
  edited here: this ticket adds no method, no route, no wire field. It does not import `isLocalReviewId` from
  `@revu/shared` at all — it imports the predicate from `lib/local-reviews.ts`, which M8.6.1 lands and which
  holds the app's single call. **If M8.1 and M8.6 have not merged, this ticket cannot start**: M8.1 defines
  the band, M8.6 defines the app's one call site and the annotation query M8.7.8 reads. The two also contest
  `palette.tsx`, so the board's stack order (M8.6 first) is the order the dependency now states.
- **`packages/app/src/styles/globals.css` is a read-only shared input** (AGENTS.md ownership list). The
  `local` chip and any local-mode surface must compose existing token utilities (`.seal`, `Badge` variants,
  `bg-panel`, `border-line`, `text-2xs`, `text-ink-mut`). **Raw hex in a component is a defect**, and a new
  `.seal`-sibling class is out of ownership.
- **`packages/app/src/api/index.ts` and `packages/app/src/fixtures/contract.ts` are read-only inputs.** Mode
  is derived from the route param, never from a fixture and never by reaching into the mock.
- **Comments and docstrings must be self-contained** (AGENTS.md; user global rule). Code may say "a local
  review has no CI" — it must never say "M8.7", "the local-reviews milestone", or reference this file.
- **Complete output only** (AGENTS.md): no `// TODO`, no stub branch, no "the other tabs follow the same
  pattern". Every gated site in the inventory is either fixed or explicitly justified as out of scope.
- **Drafts survive everything.** The review-bar copy changes touch strings only — the rollback-to-editable
  behavior, the flush-before-submit at `review-bar.tsx:101`, and the draft-deleted-only-on-success rule are
  untouched. A reworded failure detail must still tell the user their text is safe.
- **`head_moved` is a returned value, never an error** — the submit branch at `review-bar.tsx:121-129` keeps
  its three-way shape; only the `ok` branch's toast copy changes.
- **The gate is `bun run check`** (`oxlint --deny-warnings && tsc -b && bun test && vite build`), and CI runs
  the identical command. `noUnusedLocals` is on: a string moved into `mode-copy.ts` must leave no dead import
  behind.
- **Accessibility survives the omission.** Every remaining tab keeps its focus-visible ring (global
  `:focus-visible`, never suppressed), and the nav keeps an accurate `aria-label` rather than losing one.

## Landmines

- **Omitting a tab link does not omit its route.** `App.tsx:23` and `:27` still resolve
  `/pr/<local>/description` and `/pr/<local>/checks`. Miss this and the two worst strings in the inventory
  ("It was opened with an empty body", "logs live on github.com") stay one bookmark away — and the ticket's
  Verify would pass while the exit criterion "no Checks or Description tab" is technically satisfied and
  practically false.
- **`PrLayout` is list-driven, which is why M8.1's decision D-a is load-bearing here.**
  `pr-layout.tsx:279-282` finds the review in `usePullList()`; `:338` renders the 404 when it is absent. D-a
  settles that local reviews are merged into `listPulls` precisely so this ticket has something to render — if
  a future change makes them reachable only via `listLocalReviews`, every local review renders the very screen
  this ticket is deleting, and no amount of chrome work fixes it. The annotation query M8.7.8 reads is **not**
  a substitute: it carries `dirty` and `archivedPr` and nothing else.
- **`useStaleness` has no fallback.** `queries.ts:147-162` returns `null` without a list item, and computes
  `newCommits` from `item.broker.commitCount`. If M8.5 ships local list items without a populated broker
  block, the seal silently never goes gold — §7's "correct as-is" reuse would be dead code that nobody
  notices, because a quiet seal looks like a fresh snapshot.
- **`canApprove` is not a safe gate for the lock popover.** `review-bar.tsx:61` is
  `item?.broker.canApprove ?? false`, so during the list's first load (and on any list error) the lock renders
  with the github.com instruction even when the daemon reports `canApprove: true`. Gate on mode.
- **The local sentinel author parses as a GitHub org member.** `identity.ts:113-114` branches on
  `comment.user.login !== botLogin`; the sentinel's login is not the broker login, so `IdentityAvatar`
  (`avatar.tsx:106-115`) gives it the org-member ring and the github.com title, and `CommentView`
  (`comment-view.tsx:60-65`) prints "org member · github.com" beside it. This is the loudest false assertion
  on the Files tab and it is easy to miss because it is a `title`/chip, not a paragraph.
- **The rate chip cannot be prop-threaded.** `app-shell.tsx:260` renders above the router. It must be
  route-derived, and it must be *omitted* — `:56-58` renders a skeleton whenever the query has no data, so a
  "hidden by CSS" or "empty" variant is a permanent shimmer in the topbar.
- **A third `matchPrNumber` invites drift.** Two identical copies already exist; a third that spells the regex
  slightly differently breaks either the palette group or the `g f`/`g c` sequences on local reviews only,
  which is the hardest class of bug to notice.
- **There is no DOM test runner in `packages/app`.** No React Testing Library, no jsdom; every existing app
  test is a pure-module or mock-adapter test (`find packages/app/src -name '*.test.ts'` — fourteen files, none
  render a component). A unit whose Check is "the tab does not render" is **not runnable**. That is why the
  copy moves into pure modules and why the browser leg lives in the `?mock=1` walk.
- **An e2e assertion must not be a `*.test.ts`.** The gate runs `bun test` **before** `vite build`, so a
  browser test file would execute with no `packages/app/dist` present. `e2e/happy-path.ts` is a plain
  `bun run` script for exactly this reason; anything browser-driven this ticket adds goes there, and M8.11
  owns the local-review e2e leg.
- **`palette.tsx` and `lib/local-reviews.ts` are both shared with M8.6.** M8.6 adds the local-review entry to
  the **Go** group and owns the app's single `isLocalReviewId` call; this ticket gates the Checks entry in the
  **This PR** group and imports that predicate. AGENTS.md makes file ownership exclusive, which is why the
  header now names M8.6 as a dependency rather than leaving the two parallel-eligible: run parallel and
  whichever lands second either rebases `palette.tsx` or turns M8.7.4's grep red.
- **A sweep that is too eager kills the reuse story.** "branch moved", "N new commits", "base advanced",
  "head moved since sync", "re-sync" and "reconcile" all read as GitHub vocabulary to a fresh eye and are
  exactly what §7 says to keep. M8.7.7's zero-diff assertion on those four files exists to catch a sweep that
  went one file too far.
- **`?mock=1` is the only way to see this before M8.5.** It forces the pure in-browser mock with no HTTP, so
  the whole chrome is reviewable with no daemon, no git and no token — but it depends on M8.1.5 having seeded
  a fixture local review. If that fixture is not there, this ticket has no visual verification at all until
  M8.5 lands.

## Open questions

1. **What do the omitted tabs' routes do on a local review — redirect, or render a local-appropriate empty
   state?** The design omits the tab and says nothing about the route. Proposal: redirect to `files` in
   `App.tsx`, mirroring the index redirect at `App.tsx:22`. Implementer decision, but it must be *a* decision:
   leaving the routes as-is keeps two HARMFUL strings reachable.
2. **Does the rate chip disappear only while a local review is open, or whenever the workspace has no GitHub
   at all?** `getRateLimit` is a global read with no review argument, and M8.1's open question 7 explicitly
   defers the whole decision here. Route-scoped suppression is the smaller change; workspace-scoped
   suppression is the more honest one once M8.5's boot relaxation lets a daemon run with no token. Owner call.
3. **Is the `local` marker a seal or a badge, and does the `open`/`closed` state badge still render?** §3.1
   says "a `local` seal where a PR shows `#347`", but `.seal` is already the snapshot seal's class on the row
   below (`pr-layout.tsx:446-455`) and `globals.css` is read-only, so a second seal in row 1 may read as a
   duplicate. `Badge variant="outline"` is the alternative. The state badge (`:377-381`) stays meaningful under
   D1 (a review goes `closed` when archived) — confirm it should remain.
4. **Does the author row render at all on a local review?** There is exactly one author and it is the person
   looking at the screen. Options: render the local human's name with the plain initials disc; or drop the
   avatar + name from `pr-layout.tsx:410-413` entirely and let `base ← head` carry the row. The design
   specifies the sentinel `GhUser`'s *shape* (§4.1) but not whether the chrome should show it.
5. **Suppressing the author banner also removes the only header entry to the thread queue.**
   `author-banner.tsx:62-75` is the sole surfaced "Walk threads" affordance; `?queue=1` and the palette entry
   survive. The seed text says suppress, and "You authored this PR" is certainly wrong framing — but a
   contractor walking the reviewer's feedback on their own branch is arguably the single most valuable local
   flow. Confirm: suppress entirely, or keep the walk action under local-appropriate copy?
6. **How much of the Conversation tab survives "threads only"?** The literal reading drops the description
   article, the timeline and the PR-shaped empty state, leaving a page that is empty until the first thread
   exists. Confirm the local empty state is an invitation (AGENTS.md: "Empty states are invitations with a
   next action") pointing at Files, and that the tab is still worth showing when Files already renders every
   thread inline.
7. **Does the Conversation tab keep its unresolved-thread count badge?** `pr-layout.tsx:458-466` reads
   `item.broker.unresolvedThreads`. It is meaningful locally, but only if M8.5 populates it — otherwise the
   badge silently never appears. Decide whether the app tolerates that or the count is computed client-side
   from `useThreads`.
8. **What should the local submit toast actually say?** The constraint is only that it claims no API call and
   no post. "3 comments recorded on this local review" is a proposal, not a decision; the wording is an owner
   call and it is the sentence a contractor sees at the end of every review.

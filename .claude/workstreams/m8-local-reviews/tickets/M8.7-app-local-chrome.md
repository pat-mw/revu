## Goal

Make the PR chrome tell the truth on a local review. This ticket implements the frontend half of **D2**
(`LOCAL_REVIEWS.md` §3): because a local review keeps a positive-integer id, the entire `/pr/:n/*` route
family, every query key and both `matchPrNumber` regexes stay untouched — so the whole variance collapses to
a single `mode: 'github' | 'local'` derived from `isLocalReviewId` and threaded through the chrome (§7). It
lands three things. **Tabs:** Checks and Description are omitted and Conversation keeps only its threads
section, following the established "omit the group entirely rather than render it empty" precedent set by the
dev-controls capability probe — except that omitting a *tab* has no precedent today and is genuinely new.
**Identity:** `base ← head` and a `local` seal where a PR shows `#347`, no `#1000000001` anywhere (§3.1), no
author banner, and a 404 state that does not blame a GitHub App installation. **Copy:** an enumerated sweep
of every string that asserts a GitHub fact, ranked so that the actively harmful ones — those that instruct
the user to do something impossible, or claim a write that never happened — are fixed first and pinned by a
test. It also carries the two app-side pieces no other ticket owns: **D3's user-facing half** (the
uncommitted-changes banner — M8.3 detects it and M8.2 stores it, and nothing rendered it) and the **two latent
optimistic-path bugs** §6 says must not be inherited, both of which live in `state/threads.ts` and were handed
here by M8.4.7. The staleness and reconcile vocabulary is **correct as-is locally** (§7) and this ticket must
not touch it; that reuse is the strongest part of the feature and a well-meaning sweep is exactly what would
break it.

## Wave plan as actually run — and why it is more serial than the roadmap's

Recorded 2026-08-14 by the orchestrator, before dispatching, so a cold session inherits the analysis instead
of re-deriving it. **The roadmap's S2 wave table for this ticket assumes a capability the session does not
have**, and the honest response is to serialize rather than to fake it.

**The roadmap says the orchestrator "owns `lib/mode-copy.ts` — workers return copy functions, one writer
integrates."** That works when the orchestrator can merge two workers' versions of one file. This session
integrates by **copying whole files out of isolated worktrees**, so two workers who both wrote `mode-copy.ts`
produce two versions and copying one **silently discards the other**. Faking a merge is exactly the §5.5
semantic conflict the isolation exists to avoid.

**Five units write `lib/mode-copy.ts`** (.3, .4, .5, .6, .8) and a sixth extends its test (.7). **Four write
`lib/review-mode.ts`** (.1, .2, .4, .5). **Three write `pr-layout.tsx`** (.2, .3, .8, plus .7's one export).
That is three separate multi-writer files, not the one the roadmap's table plans around.

| wave | units | why |
| --- | --- | --- |
| W1 | **M8.7.10** | the harness — nothing render-shaped is assertable without it |
| W2 | **M8.7.1** | gates every other unit; defines the derivation everything branches on, and lands the source guard **before** its eight consumers exist |

**The cost is wall-clock and nothing else.** Every unit still gates independently, and no unit's result is
discarded by an integration step that cannot merge. If a future session *can* merge (workers committing to
their own branches, orchestrator merging refs), W4–W6 collapse back into the roadmap's shape.

## Units

Default execution order below. **M8.7.10 runs first** (it is appended last only because numbering never
rewinds — read the dependency, not the number): it lands the static-render harness M8.7.2, M8.7.3 and M8.7.8
assert through. Then **M8.7.1 gates every other unit** — it defines the derivation everything else branches
on. After it lands: **M8.7.2, M8.7.3 and M8.7.8 all edit `pr-layout.tsx` and must run in sequence**;
**M8.7.4, M8.7.5, M8.7.6 and M8.7.9 are mutually independent and independent of the `pr-layout.tsx` group**
(disjoint files), so all four can run in parallel with each other and with M8.7.2/M8.7.3/M8.7.8. **M8.7.7 is
the closing proof and runs last, after all nine others** — it also touches `pr-layout.tsx` (one export), which
is safe precisely because it runs after that group.

**Test-first ordering.** Two guard rails land before the code they guard. **M8.7.10** is one: without it,
"the tab does not render" is a claim, and a unit that cannot assert its own absence tends to assert nothing.
**M8.7.1**'s source guard is the other — it pins the single `isLocalReviewId` call site and the single
`matchPrNumber` definition *before* eight units start importing them, and M8.7.4 relies on it rather than
re-running a grep. **M8.7.9 is the one unit with a genuinely available red**: both bugs exist on `main` today,
so its tests are written against unmodified `threads.ts` and **must be observed failing before either fix
lands** — a green first run means the test is not exercising the path. Every other unit writes its
`mode-copy.test.ts` / render case first and observes it red on a missing module or an ungated branch.

The decomposition is chosen so that copy is *testable*. Two mechanisms, and the choice between them is not
taste: portal-rendered copy (a `TooltipContent`, a `PopoverContent`, a `DialogContent` body) **does not appear
in `renderToStaticMarkup` output at all** — verified, see Landmines — so it is only checkable if it lives in a
pure module a `bun test` file can call, which is the `components/review/error-copy.ts:1-12` pattern for
`HEAD_MOVED_TITLE` ("so the string has one source of truth the dialog renders and a test can pin"). Everything
else — tab strips, header rows, chips, banners — is inline markup, and `packages/app/src/components/ui/markdown.test.ts`
already renders a real component with `renderToStaticMarkup` in a plain `.ts` file with no DOM and no new
dependency. This ticket uses both and invents neither.

## Goal

Build a `SnapshotImmutable` for a `base…head` branch pair from one local clone, with no GitHub client,
no token, and no network — a structural sibling of `fetchImmutable` (`packages/revud/src/direct/sync.ts:155`)
that feeds the identical shape into machinery that is already provenance-blind. This is the producer half of
the milestone's one-line shape ("one new snapshot producer and one new write sink", `LOCAL_REVIEWS.md §2`),
and it implements **D3** (committed content only, plus a dirty-worktree flag), **D7** (the GitHub tier is
structurally unreachable on this path, not merely unused), and **D8** (merge base computed against the *live*
base tip, where the PR path uses GitHub's possibly-stale `pull.base.sha`).

The mapping table is `LOCAL_REVIEWS.md §5`. The important asymmetry: git produces **more** than the API path,
not less — `git diff --raw -M` yields both sides' blob SHAs, statuses and renames in one command, with no
3000-file cap and no truncatable tree. Two conventions the GitHub path *inherits* must here be **reproduced
deliberately**: an absent `PullFile.patch` means "binary or oversize", and the binary heuristic is a NUL byte
in the first 8000 bytes. Object pinning (`§5.1`) is M8.8, not this ticket; this ticket must not assume objects
stay reachable, and must not paper over their absence either.

### M8.3.1 — Hardened git seam: ref normalization, option-injection defense, repo root
**Do:** Add `packages/revud/src/direct/local-git.ts` — the only module in this ticket that constructs argv
arrays. It exports:
- `normalizeRef(input, kind: 'branch' | 'remote')` → a fully-qualified `refs/heads/<name>` or
  `refs/remotes/<name>`, or a typed rejection. Reject **before** normalizing: a leading `-`, any ASCII
  control character (including `\n`), any whitespace, an empty string, and anything already containing
  `..`. Normalization is what makes the value un-flag-like; validation is what makes it well-formed.
- `checkRefFormat(runner, cwd, qualifiedRef)` → runs `git check-ref-format <qualifiedRef>` (exit 0 = valid).
  Only ever called with an already-`refs/`-prefixed string.
- `runGit(runner, cwd, args)` → a thin wrapper that always prepends `git` and inserts `--end-of-options`
  before the first ref/rev argument and `--` before any pathspec.
- `discoverRepoRoot(runner, cwd)` → `git rev-parse --show-toplevel`, trimmed. Nothing in this ticket may
  use bare `process.cwd()`; a worktree or a subdirectory invocation must resolve to the real toplevel.
  M8.5.5 calls this once at boot and threads the result — `context.cwd` (`context.ts:167`) is an undiscovered
  `process.cwd()` and must not reach the local surface.
- `repoIdentity(runner, cwd)` → the string that keys `local_reviews`, implementing the rule M8.2 records:
  `owner/name` when `resolveRepo` (`repo.ts`) parses an origin, else the `discoverRepoRoot` path. Never an
  empty string, never a hash. It lives here because this is the module that already owns the git reads, and
  it is exported so M8.5.5 resolves it once at boot rather than per request.

### M8.3.2 — Ref resolution and merge base against the live base tip (D8)
**Do:** `resolveLocalRange(runner, cwd, { baseRef, headRef })` → `{ baseSha, headSha, mergeBaseSha, compareKey }`.
`git rev-parse --verify --end-of-options <qualified>` for each side (the **live** tip, D8 — never a recorded
SHA), then `git merge-base --end-of-options <baseSha> <headSha>`. `compareKey` is built with the *same*
`${mergeBaseSha}...${headSha}` expression as `sync.ts:422` — one string form, three dots, no variant.
Typed errors, each distinguished by the exit code actually observed, never by stderr text matching:
- `rev-parse` exit **128** → `ref_not_found` naming the ref (edge cases 5, 14).
- `merge-base` exit **1** with empty stdout → `unrelated_histories` naming **both** refs (edge case 4).
- `merge-base` exit **128** → `ref_not_found`.
- `baseSha === headSha` → `same_ref` (edge case 1). Note this is a SHA comparison, not a name comparison:
  two different branch names at the same commit are the same degenerate case.
- Before reporting `unrelated_histories`, probe `git rev-parse --is-shallow-repository`; when it prints
  `true`, report `shallow_clone` instead — a shallow clone loses the common ancestor and would otherwise be
  misreported as unrelated histories (edge case 5).
- `mergeBaseSha === headSha` (head has nothing ahead of base) is **allowed** and produces an empty review,
  not an error (edge case 2).

**Files:** `packages/revud/src/direct/local-sync.ts` (new), `packages/revud/src/direct/local-sync.test.ts` (new).

### M8.3.3 — `git diff --raw -M` → `files` + `blobIndex`
**Do:** `git -c core.quotePath=false diff --raw --no-abbrev -M -z --end-of-options <mergeBaseSha> <headSha>`.
Parse the NUL-delimited records: `:<srcMode> <dstMode> <srcSha> <dstSha> <status>\0<path>\0` — and for
`R`/`C`, `<status>\0<oldPath>\0<newPath>\0` (three fields, verified). Then:
- **`--no-abbrev` is mandatory.** Plain `--raw` abbreviates blob SHAs to 7 characters; the content-addressed
  store, `blobs.ts` and `blobIndex` all assume full 40-char SHAs.
- Map the all-zero SHA (`0000000000000000000000000000000000000000`) to `null` on both sides. That is how
  git spells "absent on this side" for adds and deletes.
- Status letters → `PullFile['status']`: `A`→`added`, `D`→`removed`, `M`→`modified`, `R###`→`renamed`
  (strip the similarity score), `C###`→`added` (a copy has no base side in the contract's vocabulary),
  `T`→`modified` (typechange has no contract status of its own).
- `blobIndex` is keyed by the **head-side path**, matching `sync.ts:190-213`: for a rename the entry lives
  under the new path and its `base` holds the *old* path's blob SHA. `removed` files keep `head: null`.
- `PullFile.sha` = the dst SHA when non-zero, else the src SHA (mirrors GitHub, which sends the pre-image
  SHA for a removed file while `sync.ts:192` still nulls the head side).
- **Skip gitlink (mode 160000) and symlink (120000) entries** — do not enter them into `blobIndex`
  (edge case 9). A gitlink's "SHA" is a commit oid the superproject usually does not even contain; handed to
  `git cat-file blob` it fails, and with the GitHub tier disabled (M8.3.6) it would land in `partial` as a
  phantom missing blob. Record them in `files` with their status so the file list stays honest, and carry
  the skip reason so M8.7 can render it.
- **No file cap.** `MAX_FILES` (`sync.ts:112`) is a GitHub pagination artifact and must not be imported here
  (edge case 10).

**Write first, red:** the parse table lands before the parser. Extract the record parser as a **pure
function** `parseRawZ(stdout: string)` so the table drives it directly with no runner at all — the runner
fake then only has to prove the argv, not the semantics.

**Files:** `packages/revud/src/direct/local-sync.ts`, `packages/revud/src/direct/local-sync.test.ts`.

**Check:** `bun test packages/revud/src/direct/local-sync.test.ts` is green and contains:

### M8.3.4 — `--numstat` counts and `-U3` patches, with the two reproduced conventions
**Do:** Two more commands, run over the same range so all three share git's diff-queue order (verified:
`--raw`, `--numstat` and `--patch` emit files in identical order):
- `git -c core.quotePath=false diff --numstat -M -z --end-of-options <mergeBase> <head>` →
  `additions`/`deletions`/`changes`. Records are `<add>\t<del>\t<path>\0`, and for a rename
  `<add>\t<del>\t\0<oldPath>\0<newPath>\0` (an **empty** third field, then two paths — verified). A binary
  file reports `-\t-`; map both counts to `0` (what GitHub reports too) and remember the flag.
- `git -c core.quotePath=false diff -M --unified=3 --end-of-options <mergeBase> <head>` → patch text, split
  into per-file sections on lines beginning with `diff --git `, then **zipped to the `--raw` list by index**
  rather than by parsing the (possibly C-quoted) path out of the header.
- Each `PullFile.patch` must contain **only that file's hunks — starting at its first `@@`**. Everything
  before it (`diff --git`, `index`, `--- a/…`, `+++ b/…`) is dropped.
- **Reproduce the absent-patch convention:** set `patch` only when the file has at least one `@@` hunk.
  A binary file (`Binary files … differ`, no hunks) and a file whose diff was suppressed leave the field
  **absent**, exactly as `mappers.ts:164-166` does for GitHub.
- **Reproduce the binary heuristic** — NUL in the first 8000 bytes — by importing `isBinaryContent`
  (`blobs.ts:83`) / the `BINARY_SNIFF_BYTES` constant rather than restating the number.

**Write first, red:** the header-bleed assertion below lands before the patch splitter. Extract the splitter
as a pure `splitPatchSections(stdout: string): string[]` and the numstat parser as a pure
`parseNumstatZ(stdout: string)`, so both tables drive functions rather than a runner.

that needs to reason about app source (`token-custody.test.ts:478`) reads it with `readFileSync` rather than
importing it. So the header-bleed guard is asserted **structurally on the emitted patch text** on the revud
side, and the *consumer* half of the same guard lands in the app package, where `diff.ts` already is.

**Files:** `packages/revud/src/direct/local-sync.ts`, `packages/revud/src/direct/local-sync.test.ts`,

### M8.3.7 — `listBranches`: the git read behind `GET /api/branches`
**Do:** M8.1.4 declares `listBranches` on the contract and adds the route; M8.6.3's pickers consume it; **no

  string the picker returns to `createLocalReview` is the string the store keys on with no re-derivation.

**Verified git behaviors** (run against this repo / a scratch repo at git 2.50.1; re-check if the pinned git
version changes):

- `git diff --raw` **abbreviates** blob SHAs (7 chars); `--no-abbrev` gives the full 40.
- `git diff --raw -M` renders a rename as `R055` plus **two** paths; `-z` makes that three NUL-terminated
  fields (`R055`, old, new).
- `git diff --numstat -z` renders a rename as `<add>\t<del>\t` then an **empty** field, then two paths.
- `git diff --numstat` renders a binary file as `-\t-\t<path>`.
- ⚠️ **CORRECTED 2026-08-18 — the original entry claimed all three formats agree in COUNT as well as in
  order, and that is false for a typechange.** What is true: `--raw`, `--numstat` and `--patch` emit files in
  **identical order** (they can even be combined in one invocation; three separate commands are recommended
  because the boundary between the NUL-delimited sections and the plain-text patch section is the fragile
  part to parse). What is **not** true is that they emit the same *number* of entries per changed path.
  Measured at git 2.50.1 over all six typechange shapes (file↔symlink, file↔gitlink, symlink↔gitlink, and a
  symlink replaced by a binary file): a `T` record is **one** `--raw -z` record and **one** `--numstat -z`
  record, but **two** `diff --git` sections — git spells a typechange as a `deleted file mode <srcMode>`
  section followed by a `new file mode <dstMode>` section, in that order, both naming the same path, because
  it has no single-section spelling for a change of object class. `--numstat` reports the **union** of the two
  sides (a symlink replaced by a two-line file is `2\t1`), and where the new side is binary the counts are
  `-\t-` and the *creation* section carries no hunk while the deletion section does. Every other status is one
  section, including a pure mode change (100644 → 100755), which git reports as `M` with `0\t0` counts and one
  hunkless `old mode`/`new mode` section. Consequence, implemented: the expected section count is a **sum over
  the status letters**, not the length of the file list.
- **`diff.external` and `color.diff = always` defeat the patch read and nothing else.** Measured at git
  2.50.1 with each set in a repository's own config: `git diff -M --unified=3` emits **zero** `diff --git`
  sections under an external differ (the other program's stdout instead), and under forced colour every
  `diff --git ` and `@@ ` line is preceded by an escape sequence so neither begins in column 0.
  `git diff --raw --no-abbrev -M -z` and `git diff --numstat -M -z` are **byte-identical** under both
  settings. So `--no-ext-diff --no-color` belong on the patch read alone; on the other two they would be
  flags no configuration could make matter.
- `git merge-base <a> <b>` with unrelated histories: exit **1**, empty stdout. With a bad ref: exit **128**.
  `git rev-parse --verify` on a missing ref: exit **128**. The exit codes distinguish the typed errors.
- `git check-ref-format 'refs/heads/--upload-pack=x'` exits **0** — it is *not* an option-injection defense.
- `git check-ref-format --allow-onelevel '-dash'` exits **129** (usage error): git read the argument as an
  option. It fails closed, but for the wrong reason, and must not be relied on as "rejected as invalid".
- `git rev-parse --verify --end-of-options <rev>` works (git ≥ 2.24) and is the real defense.
- ⚠️ **`git check-ref-format --end-of-options refs/heads/main` exits 129** — measured at git 2.50.1 while
  building the seam. **`check-ref-format` does not implement the marker at all**, so `--end-of-options` is *not*
  universally available across subcommands and must not be assumed. Consequence, already implemented: the only
  spawnable safe shape for that subcommand is a `refs/`-qualified operand with **no** marker (a string starting
  `refs/` cannot begin with `-`), `checkRefFormat` enforces that precondition fail-closed *before* spawning,
  `isHardenedArgv` carries a dedicated rule for this one subcommand, and a real-git tripwire pins the 129 so a
  future git that learns the marker turns red and the special case can be retired deliberately rather than
  lingering as folklore.
- `git rev-parse --is-shallow-repository` prints `true`/`false`.
- `git submodule add <file-path>` fails with `fatal: transport 'file' not allowed` — a local path is not an
  allowed submodule source without `-c protocol.file.allow=always`. The fixture repo therefore creates its
  gitlink with `git update-index --add --cacheinfo 160000,<sha>,<path>`, which needs no clone and no
  protocol override; `git diff --raw --no-abbrev -M` then renders it as a real `160000` entry
  (`:000000 160000 000…0 000…1 A\tvendor/sub`), which is exactly what M8.3.3 must skip.

## Constraints that bind this ticket

- **Two-half caching (`hard-constraints.md`).** The compare key is `merge_base...head`, never head alone,
  and there is no TTL. The local builder must produce a `compareKey` with the same three-dot spelling as
  `sync.ts:422` — a hyphen-or-two-dot variant would fork the cache invisibly and the immutable half would
  never be reused.
- **The frozen contract (`packages/shared/src/api/{client,types}.ts`) is read-only input.** `SnapshotImmutable`,
  `PullFile`, `CommitInfo` and `PullDetail` are consumed, never amended, by this ticket. Contract additions

  (`AGENTS.md` ownership rule).
- **D8 — the live base tip.** `baseSha` comes from `git rev-parse` at sync time, not from a stored value.
  This is the deliberate divergence from the PR path's `pull.base.sha`, and the reason a local review's
  `compareKey` can change with zero new head commits (edge case 13). Do not "stabilize" it.
- **D3 — committed content only.** The range is `merge-base(base, head)..head`, built from commit SHAs.
  The worktree is *observed* (`git status --porcelain`) but never *read into* the snapshot.
- **D7 — no GitHub client in scope.** The write path is M8.4's, but the read path sets the precedent:
  making `github` optional in `BlobProviderDeps` is a structural absence, not a conditional.
- **Email is a key, never a body (`hard-constraints.md`, edge case 26).** The synthesized `GhUser` carries
  `git config user.name`, `type: 'Bot'`, and empty URLs. `git config user.email` is the `Human.id` and must
  not appear in the `PullDetail`.
- **Honest partial, never a fabricated blob (`sync.ts:485-489`).** With tier 3 disabled, an object git cannot
  produce becomes a named `missing` SHA in `partial`. Never synthesize an empty blob to make the count work.
- **`AGENTS.md` code style.** Comments and docstrings are self-contained: they may explain *why* `--no-abbrev`
  is mandatory, and must never mention M8.3, this ticket, a phase, or the board.
- **The gate.** `oxlint → tsc -b → bun test → vite build`, green, before the PR. `noUnusedLocals` and
  `verbatimModuleSyntax` are on.
- **Test-first, and durable (`SESSION_PROTOCOL.md §4`).** Every unit's test is written and **observed red**
  before the code that satisfies it, and its Check is an assertion that runs again on every future gate. A

## Landmines

- **Patch-header bleed across files.** `parseHunks` (`diff.ts:94`) ignores everything before the first `@@`
  but nothing after it. Hand it a multi-file patch and the second file's `--- a/x` / `+++ b/x` lines are
  parsed as a **del line** and an **add line**, and its `diff --git` line as a context line. *If missed:*
  every file after the first renders with three garbage lines glued to the previous file's last hunk, and
  the line numbers drift for the rest of the file — which then anchors comments at wrong offsets.
  Each `PullFile.patch` must start at that file's own first `@@`.
- **Abbreviated blob SHAs.** Without `--no-abbrev`, `--raw` gives 7-char SHAs. *If missed:* `blobIndex`
  holds short SHAs, `store.hasBlob(sha)` (`blobs.ts:228`) never hits for a blob stored under its full SHA,
  `resolveBlobLines` returns `null`, and `classifyPendingComment` mass-classifies comments as `lost` — the
  same visible failure as the GC hazard in `§5.1`, from a completely different cause.
- **Option injection through ref names (`§8` edge case 7).** The runner takes an argv array, so shell
  injection is impossible and it is tempting to stop there. A ref beginning with `-` is read by git as a
  **flag**: `--upload-pack=<cmd>` and `--output=<path>` are argument-position code execution and file
  overwrite. `check-ref-format` does not catch it (verified: exits 0 on `refs/heads/--upload-pack=x`).
  *If missed:* an HTTP-reachable create route becomes remote command execution in the contractor's workspace.
- **`git status --porcelain` includes untracked files** (`??` rows) by default. *If missed:* a repo with a
  `node_modules` that is not fully ignored reads as permanently dirty and the D3 banner becomes noise the
  user learns to ignore — which defeats the one thing the banner exists for. Decide `-uall` vs `-uno`
  explicitly (see Open questions).
- **Gitlink SHAs are commit oids, not blob oids.** `git diff --raw` reports mode `160000` entries with real
  40-char SHAs that look exactly like blob SHAs. *If missed:* they enter `blobIndex`, `git cat-file blob`
  fails on them, and with tier 3 disabled they surface as permanently `missing` blobs in `partial` — an
  unfixable "re-sync to retry" the user can never satisfy.
- **Commit order.** `git log` prints **newest first**; the GitHub commits list is oldest first. *If missed:*
  `reconcile.ts:94`'s `findIndex(c => c.sha === draft.headSha)` slices the wrong side and "N new commits"
  reports the commits *before* the draft instead of after it.
- **Rename detection disagrees between git and GitHub.** `-M` defaults to 50% similarity; GitHub's own
  detection is not identical. *If missed:* nothing breaks, but a "parity with the GitHub path" test written
  as a byte-comparison of `previous_filename` will flake on real repos. Assert the *rule*, not the identity.
- **CI has no git identity — and a developer machine has too much.** The gate runs `bun test` on a runner
  with no global `user.email`/`user.name`, and locally under whatever global config the developer carries.
  *If missed one way:* the fixture repo's first commit fails with `Please tell me who you are` and the suite
  is red on CI while green everywhere else. *If missed the other way:* a global `diff.external`,
  `log.showSignature` or alias silently reshapes the very output the parsers are asserted against — green on
  CI, red (or worse, wrongly green) on one developer's machine. Pass `-c user.email=… -c user.name=…
  -c commit.gpgsign=false` on every commit **and** run every harness-mediated git invocation under the
  fixture's exported `GIT_CONFIG_GLOBAL`/`GIT_CONFIG_SYSTEM`-at-nonexistent-paths env (M8.3.8).
- **`bun test` runs before `vite build` in the gate** (`AGENTS.md`), so no `packages/app/dist` exists during
  tests. *If missed:* a test that reaches for built app assets (e.g. to exercise `diff.ts` through a bundle)
  is green locally and red in CI. Import `diff.ts` from source.
- **Tier-3 removal changes what `partial` means on this path.** With no API fallback, `missing` is the *only*
  outcome for an unreachable object, and M8.8's pinning is not in place yet. *If missed:* M8.3 is judged
  "flaky on rebased branches" when it is in fact reporting honestly and the mitigation is a later ticket.
- **A fixture repo that silently fails to seed a case.** `git submodule add` on a file path is refused
  outright (verified above); a symlink is a no-op on a filesystem that does not support one; `-M` does not
  fire if the "rename" is under 50% similar. *If missed:* the classification test asserts over a `files[]`
  that never contained the case, passes forever, and the gitlink/symlink skip logic is completely unguarded
  — the worst outcome available here, because the suite reports green. M8.3.8's harness self-test exists for
  exactly this and is not optional.
- **An absence assertion that has never been observed failing.** `expect(sink).toEqual([])`,
  `not.toContain('0000000')`, `not.toMatch(/github-client/)` and `not.toContain('@')` all pass on a test that
  is wired to the wrong object, never runs, or reads an empty string. *If missed:* the D7 guarantee, the
  injection defense and the email rule are all "proved" by tests that cannot fail. Every one of them carries
  either a permanent paired positive control or a recorded break-observe-revert.
- **`bun test` is process-global for the `localStorage` shim.** Any test in this ticket that touches the mock
  must call `mockDev.reset()` in `beforeAll`; the shim is one process-wide `Map`, so one file's mutations
  leak into another's. *If missed:* green locally, red on a slower CI runner, with a cause that looks like
  the code under test.

## Post-review corrections

### ⚠️ BLOCKER: a typechange made the whole snapshot unavailable, and no test could see it

**Measured, then reproduced through production `readLocalSnapshotImmutable`:** a range containing a `T` record
returned `{"ok":false,"reason":"malformed_diff","detail":"8 changed file(s) but 9 patch section(s)"}` — a
deterministic refusal of the *entire* review, on an ordinary shape (a symlinked path replaced by a real file),
reported with a detail that names the wrong cause. The `STATUS` map and the parse table both advertised `T`, so
this was a shipped defect on exactly the case the mapping table claimed to support.

**Why no test caught it:** the fixture seeded a symlink *addition* (`A`), never a typechange. It now seeds one
— `src/config`, a link in the root commit, a two-line regular file on the head branch — and the harness
verifies at seeding time that git really reports `:120000 100644 … T`, because a path that merely stopped
being a link without the pre-image ever being committed as one reads as an ordinary `M` and the case would be
silently absent again.

**The rule that replaced index-zipping, and why it stays loud.** The three streams agree on the *order* of the
paths, never on how many entries each spans. The expected section count is now a **sum** over the status letters
(`patchSectionCount`: 2 for `T`, 1 otherwise) and the cursor advances by each file's own span. A genuine
mismatch is still refused, now naming both quantities (`N changed file(s) span M patch section(s), got K`), and
a **second, independent** guard checks the *shape* of a pair rather than only its size: the first section must
introduce a `deleted file mode ` and the second a `new file mode `, scanned only before the first `@@` so no
hunk body line can satisfy it. Count alone would accept two sections in the right number that are the wrong two.

**Which section becomes the patch: both, reduced to hunks and joined.** Decided by the counts, not by taste —
`--numstat` reports a typechange once with the *union* of the two sides, so a patch carrying one side leaves the
other side's count with no line behind it. The sections themselves are never concatenated: that is the
header-bleed shape exactly. Where any section of a span carries no hunk (git declines a text diff for a binary
side) the file carries **no `patch` key at all**, which is the convention already in force — half a change is
not a smaller truth than none, its line numbers describe a file that never existed.

**The skip-by-file-mode logic was already right and is now asserted.** Every typechange changes object class, so
one side is always a symlink or a gitlink; `skipReason` reads *both* modes, so the path stays out of the blob
index on the strength of the side it left, even though its head side is an ordinary blob. A skip decided on the
head mode alone would index it and anchor a comment against a link target.

**Controls, each observed red and each revert verified byte-identical against a pristine copy:**
`patchSectionCount` forced to 1 → **21 red**; the pair-shape guard removed → **1 red, uniquely** the
"not a deletion then a creation" row.

### SHOULD-FIX: an ordinary contributor configuration defeated the patch read

`diff.external` (difftastic, delta, anything) and `color.diff = always` each turn every local review in that
repository into `malformed_diff`, because production inherits `~/.gitconfig` and the repo's own config while the
`GIT_CONFIG_GLOBAL` pin exists **only inside the fixture harness** — so the suite structurally could not see
it. Reproduced through `readLocalSnapshotImmutable` with the flags removed: both settings give
`"8 changed file(s) span 9 patch section(s), got 0"`; with them, both read `ok`.

**`--no-ext-diff` and `--no-color` are git's defaults only until a repository says otherwise**, which is the
already-named vacuous-argv-pin shape — so the guard is behavioural, in the fixture repo's own config, like
`diff.renames=false` / `diff.context=1`. It carries its own falsification: the same command **without** the two
flags is measured to yield **zero** sections under each setting, so the flags are proved load-bearing rather
than merely written.

**The record and count reads carry neither flag, on measurement.** Both streams are byte-identical under both
settings, so a flag there would be a claim nothing could falsify. The immunity is asserted instead — the two
streams are captured before and after the config is set and compared, with a non-vacuity control that they were
not both empty.

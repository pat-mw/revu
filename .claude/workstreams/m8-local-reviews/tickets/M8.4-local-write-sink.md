## Goal

Deliver local implementations of the four write verbs — `submitReview`, `replyToThread`, `resolveThread`,
`addReaction` — in a module that has **no GitHub client in scope**. This is the second of the two new pieces
the whole milestone reduces to (`LOCAL_REVIEWS.md §2`): one new snapshot producer (M8.3) and one new write
sink (here). It implements **D7** (`§3`) as its spine: the absence of a GitHub client is structural, not
conditional, and is asserted by a test that fails if one is introduced. It also implements the write
semantics of `§6` — every verb returns a **complete, well-formed** value because the app's optimistic
mutations copy fields back out of the response, so a stub returning the old value makes an optimistic update
silently revert (which reads as a bug rather than an error); `head_moved` stays a 200-level value and matters
*more* locally than for a PR; and `prefixBody` stamping is skipped entirely, with the real `Human.id` carried
on `commentAuthors` instead. Verdicts stay meaningful with `canApprove` true (`§6`), so the approve gate that
exists for GitHub's self-review rule has no local counterpart.

This ticket does **not** wire dispatch — `isLocalReviewId(n)` routing lives in M8.5. It delivers the module
plus its port, tested against fakes.

## Units

code it constrains, the unit's **Do** says so and names the red it expects. **M8.4.1 must land first** — every
other unit imports its port type, and its test file is written *before* the module so the first run is red on
a missing import. **M8.4.6 should land second**, as a failing-then-passing guard rail, so the units that

in and can run in parallel on separate commits. **M8.4.7 and M8.4.9 depend on .3/.4/.5** (both consume their
return values and persisted state as fixtures).

### M8.4.1 — The module and its port, with no GitHub client in scope
**Do:** Create `local-writes.ts` exporting a `LocalWriteDeps` interface and four stub-free verb functions.
The port carries exactly: the narrow local-store slice (`getLocalSnapshot`, `putLocalSnapshot`,
`putLocalThread`, `putLocalReviewSummary`, `getLocalDraft`, `deleteLocalDraft`), `session: Session`,
`resolveHead: () => Promise<{ sha: string; commitCount: number }>`, an injected
`nextEntityId: () => number` (the durable allocator M8.2.2 owns — see M8.4.2), and `now?: () => string`.
It deliberately carries **no `github`**, **no `WriteDecorator`**, and **no `CommandRunner`**.

Two omissions are decisions, not oversights, and belong in the module docstring:
- **No `WriteDecorator`.** Its two methods are `decorateBody` (stamping — dropped by `§6` "No stamping") and
  `recordWrite` (the audit journal — dropped by `§8` edge case 25, local writes are not journaled). Both are
  inert locally, so the seam is omitted rather than injected as a double no-op.
- **No `CommandRunner`.** Head resolution arrives as an injected `resolveHead` function so the module spawns
  no subprocess at all, and so the ref-name hardening M8.3 owns (`§8` edge case 7 — a ref beginning with `-`
  is read by git as a flag) is not duplicated or half-reimplemented here.

Define the store slice as its own interface in this file, not as `Pick<DirectStore, …>`, so M8.4 is
completable against M8.1 alone and M8.2's v4 tables satisfy it structurally when M8.5 wires them.

**Test first.** Create `local-writes.test.ts` *before* `local-writes.ts`, holding `makeLocalDeps()` — the one
typed `LocalWriteDeps` factory every test in this ticket constructs deps through — and run it: red on the
missing module. Then write the module and take it green.

**Files:** `packages/revud/src/direct/local-writes.ts` (new),
`packages/revud/src/direct/local-writes.test.ts` (new).
**Check:** `local-writes.test.ts` asserts `Object.keys(makeLocalDeps()).sort()` equals exactly
`['deleteLocalDraft', 'getLocalDraft', 'getLocalSnapshot', 'nextEntityId', 'now', 'putLocalReviewSummary',
'putLocalSnapshot', 'putLocalThread', 'resolveHead', 'session']` — the factory sets `now` explicitly (also
what makes timestamps deterministic), so the key set is exact. Because the factory is typed `LocalWriteDeps`
and is the only constructor of one in the package, a member added to the port either fails compilation in the
factory or fails this assertion — the port's shape is pinned on **every** gate, not on the day it was written.
**Negative control** (the Check asserts an absence): add `github: GithubClient` to `LocalWriteDeps` and
`github: throwingGithubClient()` to the factory, observe the key-set assertion red, revert and observe green;
record both runs in the Log. `bunx tsc -b` clean and a `grep` over the module corroborate the docstring
wording; neither is the Check.

### M8.4.2 — Local id minting: entity ids and thread ids
**Do:** Mint comment and review-summary ids from `LOCAL_ENTITY_ID_BASE` (M8.1), strictly positive and
monotonic across daemon restarts. **The high-water mark's home is settled**: M8.2.1 seeds a `meta` row and
M8.2.2 exposes `nextLocalEntityId()` as a read-and-bump inside one transaction. A `MAX(id)` scan was rejected
because comment ids live inside the stored `ReviewThread` documents rather than in a column, so the scan would
mean parsing every thread row on every mint. This module therefore holds **no persistence of its own**: it
takes the allocator as the injected `nextEntityId` on M8.4.1's port, so M8.4 stays completable against M8.1
alone (the unit tests pass a counting fake) and M8.5 wires the durable one.

Mint thread ids in the shape **M8.1.3's mock already minted** (M8.1's open question 8 fixes it, because D6
makes the mock the spec and M8.1 merges first) — unique per local review and containing no `/`, since they
travel as a single URL path segment.

Write `local-ids.test.ts` first — the band and statelessness cases are red on the missing module — then mint.

**Files:** `packages/revud/src/direct/local-ids.ts` (new), `packages/revud/src/direct/local-ids.test.ts` (new).
**Check:** `local-ids.test.ts` asserts, all durable:

  `>= LOCAL_ENTITY_ID_BASE`, `Number.isSafeInteger`, strictly increasing, outside the mock's `700_000_000`
  band, and above GitHub's ~1e9–3e9 range.
- **(b) Statelessness, asserted behaviorally rather than by `grep`.** Mint three ids through allocator fake A,

### M8.4.3 — `submitLocalReview`: five phases become three
**Do:** Implement submit. The GitHub path's five phases (`writes.ts:308-447`) reduce to three:
1. **Head guard** — `resolveHead()` vs `input.expectedHeadSha`. On mismatch return
   `{ status: 'head_moved', currentHeadSha, newCommits }` as a **value**, post nothing, touch no draft.
2. ~~Approve gating~~ — dropped: `canApprove` is true locally (`§6`), so `forbidden` is unreachable. The
   `SubmitResult` variant stays (frozen contract) but nothing returns it.
3. ~~Idempotency re-check~~ and ~~the 422 path~~ — dropped as having no local analogue (`§6`): a lost network
   response and server-side re-validation are the only reasons they exist.
4. **Materialize** — one local `ReviewThread` per `PendingComment` (locally minted thread id, positive comment
   ids), plus one local `ReviewSummary` using `EVENT_STATE` (`writes.ts:57-61`) verbatim. Comment `user` is the
   sentinel `GhUser` from `§4.1` (git-config **name**, `type: 'Bot'`, empty `avatar_url`/`html_url`, **never**
   the email). Bodies are stored verbatim — no `prefixBody`. Append the new threads to the local snapshot's
   mutable half and record each new comment id in `commentAuthors` keyed to `session.human.id`. The
   `ReviewSummary` goes to `putLocalReviewSummary` **only**: per M8.1's decision D-b it is never appended to
   `snapshot.mutable.reviews`, which stays `[]` on a local review forever so §4.1's and §7's "always empty"
   holds after the first submit. `mutable.issueComments` is likewise never written.
5. **Delete the draft last, and only on confirmed success** — after the snapshot/thread/summary writes have
   returned. `§8` edge case 19: locally this is trivially satisfiable and must still be coded that way.

**Files:** `packages/revud/src/direct/local-writes.ts`, `packages/revud/src/direct/local-writes.test.ts`.
**Check:** Tests, against the M8.4.8 harness: (a) a submit of 2 pending comments produces 2 threads whose
comments each have a distinct positive id `>= LOCAL_ENTITY_ID_BASE`, and the snapshot read *after* submit
already contains them; (b) `expectedHeadSha` mismatch returns `status: 'head_moved'` and `getLocalDraft`
still returns the draft; (c) a store fake that throws on the thread write leaves the draft present (assert
`getLocalDraft !== null` after the rejection); (d) no comment body and no `ReviewSummary.body` matches
`/^\*\*.+\*\*/`; (e) `commentAuthors[id] === session.human.id` for every created comment; (f) the sentinel
`GhUser` JSON contains no `@`; (g) D-b — after a successful submit the persisted snapshot's
`mutable.reviews` and `mutable.issueComments` are both still `[]`, while `listLocalSubmittedReviews` carries
the minted summary.

### M8.4.4 — `replyToLocalThread` and `resolveLocalThread`
**Do:** Reply appends a locally-id'd `ReviewComment` to the stored thread and returns it, mirroring the mock
oracle's field derivation (`adapter.ts:379-401`): `in_reply_to_id` = the thread's first comment id,
`pull_request_review_id` carried from that first comment, `path`/`line`/`side`/`subject_type` from the thread,
`reactions` zeroed (the shape at `threads.ts:33-46`). An absent thread, or one with no comments, is a typed
`not_found`. Resolve flips `isResolved`, sets `resolvedBy` to the sentinel login (or `null` on unresolve),
persists, and returns **the whole stored thread** with every other field unchanged — `isOutdated` in
particular must be carried, not recomputed or defaulted.

**Files:** `packages/revud/src/direct/local-writes.ts`, `packages/revud/src/direct/local-writes.test.ts`.
**Check:** A test resolves a thread whose stored `isOutdated` is `true` and asserts the returned thread still
reports `isOutdated: true` and `isResolved: true`; a second asserts `resolveThread(..., false)` returns
`resolvedBy: null`; a third asserts a reply's returned `id` is positive and appears in the thread on the next
`getLocalSnapshot`; a fourth asserts an unknown `threadId` throws `ApiError` with code `not_found`.

### M8.4.5 — `addLocalReaction`
**Do:** Locate the comment by id across the local snapshot's threads, bump the rollup, persist, and return the
**new** rollup. `mutable.issueComments` is always `[]` locally (`§4.1`), so the review-vs-issue endpoint
classification at `writes.ts:560-566` collapses to a single lookup — an id found nowhere is a typed
`not_found`. Keep the mock's dedup semantic (`adapter.ts:465-472`): a repeat of the same reaction returns the
rollup unchanged. That is honest here (there is exactly one local author) and is **not** the stub `§6` warns
against — the app already reconciles an unchanged rollup silently (`state/threads.ts:330-336`).

**Files:** `packages/revud/src/direct/local-writes.ts`, `packages/revud/src/direct/local-writes.test.ts`.
**Check:** A test asserts a first reaction returns `total_count` incremented by 1 and the persisted snapshot
agrees; a repeat returns the identical rollup; an unknown comment id throws `not_found`.

### M8.4.6 — The D7 structural test
**Do:** A dedicated test file asserting the local write path cannot reach GitHub. Land it **red, before** the
units it constrains (`.2`, `.3`, `.4`, `.5`, `.8`, `.9`) — a guard written afterwards encodes what the code
does rather than what it must never do. Four assertions:
1. **Import-specifier scan** — parse only the `import … from '<spec>'` specifiers out of the local module set
   and assert none resolves to `./github-client`, `./write-decorator`, `./command-runner`, or any module whose
   basename contains `github`. Scanning specifiers rather than whole-file text is what keeps the docstring
   explaining the absence from tripping the scan — the same technique `audit-integrity.test.ts:116-125` uses
   to keep a comment naming a banned SQL construct from failing the ban.
2. **Transitive closure** — walk the relative-import graph from `local-writes.ts` and assert
   `github-client.ts` is not reachable at any depth, so a helper cannot smuggle a client in.
3. **Egress vocabulary** — assert the module body contains no `fetch(`, no `https://`, no `api.github.com`,
   and no `Bun.spawn` (the port takes `resolveHead`, so the module spawns nothing either).
4. **The scanner cannot go quietly vacuous.** Two self-assertions: the scanned file set is exactly
   `['local-ids.ts', 'local-write-fakes.ts', 'local-writes.test.ts', 'local-writes.ts']` and every one of them
   read non-empty (a renamed or mistyped path would otherwise make the whole file pass by scanning nothing);
   and the specifier extractor, run over an **inline fixture source** that imports `./github-client`, reports
   that specifier — so a regex that stops matching fails here instead of silently permitting everything.
   The test-support files are in the set deliberately: the local tests construct no GitHub client, and that
   absence is the point (`Verify` 3).

**Files:** `packages/revud/src/direct/local-write-isolation.test.ts` (new).
**Check:** `bun test packages/revud/src/direct/local-write-isolation.test.ts` green, with the four assertions

### M8.4.7 — Optimistic-path convergence, and the two bugs not inherited
**Do:** Pin the fields the app copies back out of each response, and make sure the two latent direct-mode
optimistic bugs are not inherited (`§6`):
- **Unconditional stamping in the synthetic reply** (`state/threads.ts:161`) — `syntheticReply` always calls
  `prefixBody(session.human, body)`, so the optimistic comment briefly renders `**Name** (role)` as literal
  body text before the unstamped server comment swaps in.
- **Empty-login attribution on resolve** (`state/threads.ts:292`) — the optimistic flip sets
  `resolvedBy: { login: session.brokerLogin }`, which is `''` in direct mode.

The sink's own obligation is to return values that make the optimistic path converge on the truth. **The
app-side half is M8.7's** (unit M8.7.9): both fixes live in `packages/app/src/state/threads.ts`, this ticket's
Surface is `revu:revud`, and today's unconditional stamp is wrong in *direct* mode too — so it is a small real
behavior change to existing PR reviews, not a local-only branch, and it belongs with the app tickets. This
unit owns only the response-shape contract that makes convergence possible.

**Files:** `packages/revud/src/direct/local-writes.test.ts`.
**Check:** A test asserts, field by field, that each verb's return value is fully populated for exactly the
fields the app reads back: reply → `id` (positive), `in_reply_to_id`, `path`, `line`, `side`, `subject_type`,
`reactions`, `user`, `body`; resolve → `isResolved`, `isOutdated`, `resolvedBy`; react → the whole
`ReactionRollup`; submit → a `ReviewSummary` with a positive `id`, a mapped `state`, and a `commit_id` equal

### M8.4.8 — The in-memory local harness (lands before M8.4.3, ahead of its number)
**Do:** One shared test-support module so `.3`/`.4`/`.5`/`.9` are written against a single fake and a new port
member has exactly one place to appear. It exports `createFakeLocalStore()` — a `Map`-backed implementation of
the six store-slice methods, with a `throwOn` option naming a method that rejects, which is what drives the
persist-failure cases, and read-backs for what was written (including the submitted-summary list M8.4.3's
Check (g) reads) — plus `countingEntityIds()` (a strictly-increasing allocator fake starting at
`LOCAL_ENTITY_ID_BASE`) and `fixedHead(sha, commitCount)`. Modeled on `github-write-stubs.ts`: test-support

because the port has nowhere to put one. Real-store durability belongs to M8.2; this fake is what keeps M8.4
completable against M8.1 alone.

**Reads must return copies.** `getLocalSnapshot` returns a structural clone, never the stored object — the
whole ticket's persistence assertions ("the snapshot read *after* submit already contains them") are vacuous
if the sink mutated an object the fake still holds by reference.

**Files:** `packages/revud/src/direct/local-write-fakes.ts` (new),
`packages/revud/src/direct/local-writes.test.ts`.
**Check:** A `describe('the harness cannot make a persistence assertion pass by aliasing')` in
`local-writes.test.ts`: (a) two successive `getLocalSnapshot(id)` calls return objects that are deep-equal but
**not reference-equal**, and mutating the first does not change the second; (b) a store built with

### M8.4.9 — The full local loop, and the draft-survival matrix
**Do:** Own the two acceptance behaviors no per-verb unit covers: the four verbs composing over one persisted

**Files:** `packages/revud/src/direct/local-writes.test.ts`.

## Constraints that bind this ticket

- **`RevuApi` and the wire types are frozen** (hard-constraints). All four verbs keep their exact signatures;
  `SubmitResult` keeps all three variants even though `forbidden` becomes unreachable locally. Nothing in this
  ticket edits `packages/shared/src/api/client.ts` or `types.ts` — AGENTS.md lists both as read-only inputs.
- **`submitReview` returns `head_moved` as a 200-level VALUE, never an error** (hard-constraints; `§6`
  restates it and notes it matters more locally, because an amend or rebase moves head with no PR event to
  notice it).
- **Drafts survive everything; a draft is deleted only on confirmed submit success** (hard-constraints;
  `§8` edge case 19). Locally that success is trivially reachable, which is exactly why the ordering must be
  coded explicitly rather than assumed.
- **D7 — the local write path has no GitHub client in scope, structurally** (`§3`, `§8` edge case 24, and M8's
  exit criterion "enforced structurally … and asserted by a test that fails if one is introduced").
- **D4 / edge case 25 — no local write is journaled to `audit_log`**, and no synthetic id ever enters
  `audit_log.pr`. That is why the `WriteDecorator` is omitted rather than injected: an injected decorator
  could later be swapped for the broker one and start journaling local ids into the collector's view.
- **Email is a key, never a body** (hard-constraints; `§8` edge case 26). The synthesized `GhUser` carries the
  git-config **name**; `Human.id` (the lowercased email, `identity.ts:16-18`) appears only in
  `commentAuthors`, which the type at `types.ts:370-372` states is never rendered.
- **Locally minted ids are positive and band-disjoint** (`§8` edge case 17) — negatives are reserved for the
  app's optimistic synthetics.
- **Code style (AGENTS.md):** comments and docstrings are self-contained. Nothing in this module may reference
  M8.4, this board, a PR number, or any tracking artifact. Complete output only — no stubs, no TODOs.
- **TDD (hard-constraints):** every unit lands with its tests; `bun run check` green before the PR.

**Four questions this ticket used to carry are settled elsewhere; do not re-open them.**

- **The local `ReviewSummary` does not enter `snapshot.mutable.reviews`** — M8.1's decision D-b. It is

- **The two app-side optimistic fixes land in M8.7** (unit M8.7.9), not here — see M8.4.7. This ticket owns

## Landmines

- **A verb that returns anything less than the complete value silently reverts the UI.** `state/threads.ts:308-313`
  copies `isResolved`/`isOutdated`/`resolvedBy` out of the resolve response, and `:362-372` overwrites the
  cached rollup with the reaction response. A resolve that rebuilds the thread and defaults `isOutdated` to
  `false` will flip an outdated thread back to current, with no error anywhere. Return the stored object with
  only the intended fields changed.
- **Submit returning `ok` with nothing materialized is worse than an error.** `useSubmitReview`
  (`state/drafts.ts:274-283`) clears the draft and invalidates the snapshot on `ok`. If the threads were never
  written, the draft vanishes and nothing appears — exactly the "draft lost" outcome the product exists to
  prevent. Persist first, delete the draft last.
- **Without `commentAuthors`, own-comment detection fails on every local comment.** `isOwnComment`
  (`identity.ts:196-208`) tries the write log, then a `viewerLogin` match, then the smuggled name. With no
  stamping the name path returns `kind: 'github'`, and `viewerLogin` is either absent (boot relaxation) or a
  real GitHub login that never equals the sentinel. Populating `commentAuthors` is load-bearing, not
  decorative.
- **A rebase can move head with an unchanged commit count**, so `newCommits` computed as a count delta is `0`
  while `head_moved` is true. That is honest, but a surface reading `newCommits === 0` as "nothing changed"
  will mislead. The under-reporting mechanism (`§8` edge case 12 — a rebase preserves author date, so the
  fallback heuristic silently under-counts) is M8.8's to fix; do not paper over it here with a fabricated
  count.
- **Do not "fix" the reaction dedup.** Returning an unchanged rollup for a repeat reaction is the mock's
  semantic (`adapter.ts:469-472`) and the app reconciles it silently. `§6`'s warning is about a verb that
  *always* returns the old value, not about honest idempotence.
- **Do not inline `git rev-parse` here.** A ref arriving over HTTP and beginning with `-` is read by git as a
  flag (`§8` edge case 7), and nothing validates command arguments today. Head resolution is injected;
  hardening belongs to M8.3's resolver.
- **`conflict` becomes unreachable but the type stays** (`§6`). Deleting the variant would touch the frozen
  contract and break the mock's conformance leg.
- **The shared mock store leaks across test files** (memories/known-landmines.md). Any test in this ticket that
  drives `createMockApi`/`mockDev` must `mockDev.reset()` in `beforeAll`. Prefer an in-memory store fake and
  avoid the mock entirely in the unit tests — only the M8.11 conformance leg needs it.
- **A whole-file `not.toMatch(/github/i)` scan will fail on its own docstring.** Scan import specifiers and
  walk the import graph; `audit-integrity.test.ts:116-125` is the precedent for keeping the ban precise enough
  that documentation does not trip it.
- **`store.deleteDraft` throws on a failed write** (`store.ts:462-466`). If the local port's delete is the last
  step and it throws after the threads landed, the caller sees a rejection for a submit that actually
  succeeded — and a retry re-materializes duplicate threads (there is no idempotency re-check locally). Decide
  and document the ordering: the safest is threads → summary → snapshot → draft delete, with a delete failure
  surfaced as `persist_failed` and the resubmit hazard noted, mirroring the accepted duplicate-on-retry window
  documented at `writes.ts:457-463`.

## Testing exceptions

One assertion this ticket genuinely cannot make from `packages/revud`, recorded rather than faked:

- **M8.4.2 (c) — thread-id shape *equality* with the mock.** The sink and M8.1.3's mock must mint the same
  shape (D6 makes the mock the spec), but this package cannot compare them directly: `@revu/app` exports only
  `./mock` (`packages/app/package.json`), which is the whole `createMockApi` surface, and importing it drags
  in the process-wide `localStorage` shim every driving test must `mockDev.reset()` (Landmines) — an

  change on either side fails; and M8.11's conformance leg runs the same local-review suite over the mock and
  the direct transport, so a divergence fails there. Not covered: a change made to both the mock and the
  golden fixture in one commit — a deliberate contract move, which is the pre-merge review's job.

## Goal

The landing audit of 2026-09-02 read every ticket, every exit criterion and every design section against the
code on the tip. It found the **behaviour** sound almost everywhere; what it found missing was **proof**. This
ticket is the whole of that debt, collected in one place: two majors that survived a three-lens refutation,
thirty-six minors whose remedy the audit itself named as a test or a control, and three Verify items the
tickets honestly recorded as `partially-proven`.

**Scope: tests, controls and test harness only. No product behaviour changes.** Twelve units touch a file that
is not a `*.test.ts`, and each does so without changing what the daemon or the app does. Verify item 6 is the
exact allowlist; this is why each one is inside the scope rule:

- **Dead code removed.** **M8.14.24** deletes `normalizeRef`, a seam function with **no production caller**
  (its only callers are two test files). Deleting unreachable code changes no behaviour; the create path
  already runs the shared validator and keeps running it.
- **Pure code motion, so a sequence becomes drivable.** **M8.14.6** (`index.ts` → `composeDirectApi`),
  **M8.14.26** (`reconcile-plan.ts` + `reconcile-dialog.tsx`), **M8.14.27** (`threads.ts`) and **M8.14.32**
  (`review-mode.ts` + `app-shell.tsx`) each lift an inline closure or derivation into an exported function and
  call it from the site it came from — so a thing currently only assertable by reading source order becomes
  assertable by driving it. The audit names this remedy itself ("lift the head-move-before-submit sequence into
  a pinnable step … a test-harness change with no behaviour change").
- **Test-support files, not product.** **M8.14.7** wraps `Bun.fetch` inside three guards (a preload, an e2e
  guard, a tripwire); nothing in `packages/revud/src` or `packages/shared/src` calls `Bun.fetch` today, so the
  wrap widens the guard, not the product. **M8.14.9** adds `no-network-probe.ts`, a new entry in the same
  category as the preload beside it — nothing in the daemon imports either.
- **Comment only.** **M8.14.10** edits a comment in `local-surface.ts` and nothing else in that file.
- **Scripts.** **M8.14.20**, **M8.14.21** and **M8.14.22** register legs and add an `import.meta.main` guard
  plus three exports in `scripts/conformance-matrix.ts` — the matrix runner, which ships nothing.
- **The one real specification change, and it is gated.** **M8.14.23** touches the mock, which *is* the
  contract's specification. It runs only if the owner picks **Open question 2 (a)**; under 2(b) it does not
  run at all.

Everything else adds assertions, fixtures, runners and matrix legs.

**Why one ticket rather than thirty-seven.** Every unit here shares one acceptance rule — a proof that cannot
go red is not a proof — and every unit's Check is written to be falsified by a control rather than merely to
pass. Splitting them would multiply the ceremony and lose the single place a later reader can ask "what did
the audit find, and where did it land?".

**What this ticket is not.** It closes no design question and adds no capability. Where an audit finding could
only be closed by changing what a producer does — the mock always emitting an empty compare, no seeded mock
fixture being dirty — the choice is written up in **Open questions** with both answers as alternative units,
and the owner decides before that unit starts.

## Goal

**A broker daemon served no reviews of local branches at all.** Every id in the reserved local band answered
`not_found`, `POST /api/local-reviews` answered "this daemon does not serve local reviews", and the branch
listing answered the same — while a direct daemon in the same clone served the whole loop.

The cause was not a missing capability. Everything the surface needs was already reachable from broker boot:
the store is open, the runner is the same one direct mode uses, the session is real from boot, and the
branch-pair listing the archive check reads is already passed there (broker binds it to its poll loop's own
client). The only thing missing was the assembly — `mainDirect` discovered a repository and built a
`createLocalReviewSurface`, `mainBroker` did not, and nothing in the type system noticed, because the api's
`localReviews` dependency is optional by design (a daemon with no repository must have none).

This is a **defect against a decision already recorded**: `docs/agent/LOCAL_REVIEWS.md` D5 says local reviews
are "a capability inside direct/broker mode, not a fourth mode", and `resolveGithubRequirement`'s own docstring
says the capability "rides inside direct and broker mode". The boot was behind its own design.

It was found from outside: a client workspace running broker mode went to pull the local-review pipeline in and
had nowhere to reach it.

## Units

### M8.18.1 — One assembler, so no boot can omit the surface
**Do:** Move the local-surface assembly out of `mainDirect` into an exported `createBootApi(parts)` that takes
the resolved context plus the store, discovers the repository toplevel from the context's working directory,
builds the surface over the DISCOVERED root, and assembles `createDirectApi` with the GitHub half exactly as
the context holds it. Each boot then passes only what is genuinely its own: broker its poll cache, its
credential-bound branch-pair listing and its write decorator; direct nothing at all. Fixing only the broker
call site would have left the same class of defect one boot away.

**Files:** `packages/revud/src/index.ts`.
**Check:** `tsc -b` and `oxlint` clean; the direct startup line is unchanged (its byte-for-byte test still
passes), and `mainBroker` no longer calls `createDirectApi` directly.

## Open questions

- **The startup line says nothing about the capability.** Neither boot prints whether a local surface was
  assembled, so a daemon started outside a repository is silently without one and the first evidence is a
  `not_found` on the band. Direct mode has always been this way and the line is pinned byte-for-byte by a test
  other suites read the bound port out of, so nothing was changed here. A `local=` fact on both lines, added
  deliberately with that test updated, would make the absence discoverable at boot.
- **A cold poll cache hides the local rows.** The review list a broker serves is the merge of its poll cache
  with this workspace's local reviews, and the merged path asks the poll source unconditionally — so before the
  first successful credential poll (a container whose credential has not landed yet, a GitHub it cannot reach)
  `GET /api/pulls` answers `broker_unreachable` and the local reviews go with it, though nothing about them
  needs the credential. Observed live on a reads-only daemon with no credential file: every other local route
  answered, the list did not. Serving the local half alone would be the silent degradation this codebase
  refuses everywhere else — a list that quietly drops the pull requests reads as an empty inbox, not as an
  outage — so nothing was changed here; the honest fix is a list that can say which half is missing, which is a
  contract change. The owner's call.

- **Broker mode's docs still carry a "not a shipped boot option" callout** while `mainBroker` exists and is
  what the client is running. Left alone here: it is a product-status claim, not a fact this change moved.
